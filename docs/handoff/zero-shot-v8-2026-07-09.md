### 残 findings 8 施策の実装完了 (2026-07-09 追加、 design doc §3.8)

§3.7 で v8 config を確定した後、 review で未実装だった findings をコード側で完遂。
GPU 実測は次セッション (vast.ai instance destroy 済) だが、 各施策は単体テスト
40+ で契約 pin 済 + backward-compat は byte-for-byte 一致で保証。

**予測 wall-clock 更新** (§3.8 累積効果):

- 現行 sec/step: 10.74 (smoke2 baseline)
- 予測 sec/step: **7-8** (T-empty +2-3% × T-npy +5-10% × T3 +2-5% × T6 +5-10%、
  掛算ではなく overlap 保守見積)
- **単一 A100 SXM4**: 51 日 → **30-38 日** (最良 30 日)
- **4x A100 SXM4 DDP**: 9-11 日 → **6-8 日** (最良 6 日)
- **前処理 (P3/P4/P5)**: 8-10h → **2-4h**

詳細は [design doc §3.8](../design/zero-shot-v8-dataset-scaling-plan.md#38-残-findings-実装完了-2026-07-09-追加ランディング) 参照。

### 実測 (vast.ai A100 SXM4 80GB × 1)

| Test | 設定 | sec/step | Non-finite skip |
|---|---|---|---|
| Test 1 (baseline) | bf16-mixed + SCL + DINO + bucketing、 100 batches | 14.0 | 0/100 |
| **smoke2** ⭐ | + 5 施策 + KL v2、 300 batches | **10.74** | **6/300 (2%)** |
| smoke3b | + `--precomputed-mel` | 11.46 | 6/300 (2%) |

**Improvement**: **-23% sec/step** vs Test 1 (real config で)

### batch size 探索 (追加、 A100 SXM4 80GB × 1)

| batch | VRAM peak | utts/sec |
|---|---|---|
| **64** ⭐ | 40GB | **5.96** (最高) |
| 192 | 63GB | 5.82 |
| 224 | 73GB (91.6%) | 5.15 (-14%) |
| **256** | OOM | — |

→ **compute-bound、 batch 増加で throughput 悪化**。 **v8 本走は batch=32/GPU × 4x DDP (effective 128)** で単一 GPU の最良 utt throughput を維持しつつ並列化。

## v8 本走の推奨構成

**Plan B: 4x A100 SXM4 DDP、 batch=32/GPU (effective 128)**

見積: **9-11 日 / ~$1,120** (storage 込 $5.19/hr × 240 hr)

CLI: [design doc §3.7 参照](../design/zero-shot-v8-dataset-scaling-plan.md#37-全-smoke-test-完了--最終見積-2026-07-09-セッション終了時点)

**除外フラグ (実測で不採用)**:
- `--compile`: torch inductor+triton kernel compile crash
- `--precomputed-mel`: GPU-bound で -6.5% 遅い
- `--enable-length-bucketing`: +34% 逆効果

## 学習開始手順 (次セッション用)

### 1. vast.ai instance 準備 (4x A100 SXM4 想定)

```bash
# search + rent
vastai search offers 'num_gpus=4 gpu_name=A100_SXM4 reliability>0.995 duration>21 disk>1700 inet_up>3'
vastai create instance <ID> --image nvidia/cuda:12.8.1-devel-ubuntu24.04 \
    --disk 1700 --label piper-v8-fullrun \
    --env "-e WANDB_API_KEY=... -e HF_TOKEN=..."
```

### 2. 環境セットアップ (30 分)

```bash
ssh root@<ip>
# torch 2.11 + venv + repo
cd /data && git clone https://github.com/ayutaz/piper-plus.git piper-plus
cd piper-plus && git checkout feat/zero-shot-v8-dataset-scaling
python -m venv /data/piper/.venv
/data/piper/.venv/bin/pip install torch==2.11.0+cu128 torchaudio==2.11.0+cu128 \
    --extra-index-url https://download.pytorch.org/whl/cu128
/data/piper/.venv/bin/pip install -e src/python/[train,super-mas]
```

### 3. データセット + CAM++ 再構築 (~12h、 ~$18)

**注意 (2026-07-09)**: vast.ai instance 44096702 は **削除済** (storage 課金停止のため)。
v8 dataset は破棄済みで、 次セッションでフル再構築が必要。

再構築手順 (推定時間):
- 生データ DL (moe-speech-plus + LibriTTS-R + AISHELL-3 + CML-TTS + CV pt): **3-5h**
- `prepare_multilingual_dataset.py` (P2 並列 VAD 有効): **~8h** (旧 30h から短縮)
- `extract_speaker_embedding.py` (fixed_frames + IO binding): **~30 min**
- `precompute_mel` (--precomputed-mel 使う場合、 実測で効果なしのため任意): 85 sec
- **合計: ~12h / ~$18** (単一 A100 で)

再構築が完了したら:

└── cache/                     # audio_norm .pt + spec .pt
/data/piper/models/campplus.onnx  # HF: ayousanz/campplus-onnx (private)

前処理 script の使用例は [`docs/handoff/zero-shot-tts-handoff-2026-06-20.md`](zero-shot-tts-handoff-2026-06-20.md) 参照。
