## 1. 結論

1. **最も有望なのは、decoder を推論で実際に通る経路の z でも学習させる案 (付録 1 の A)**。
   - 今の decoder は、学習では posterior (実録音から作る) の z しか見ていない。推論では text → prior → flow で作った z を受け取る。
   - 計画書 §7.6・§7.10 では、ざらつき (2.8 kHz より上のずれ) が、decoder 単体の再構成より、prior から作った z を入れた合成で大きく出た (再構成 1.9 dB、合成 3.0 dB)。この案は、話者の似方とざらつきの両方に効く見込みがある。
   - 近い方法として、SC-GlowTTS (arXiv 2104.05557) がある。TTS が予測した spectrogram で vocoder を学習し直し、学習にいない話者の類似度が上がったと要旨に書かれている。
   - 大きさ・速さ・ランタイムは変わらない。既存の `tools/train_decoder_only.py` を延ばして作れ、1 本 $3〜6 で試せる。
   - 過去のコミット・設計書を調べた範囲では、prior/flow の経路の z で decoder を学習した記録はない。
2. **音質は、学習のときだけ足す損失・判別器で上げる余地がある (付録 2)**。
   - 今の損失と判別器は、振幅しか見ていない。候補は次の 3 つで、どれも過去に試した記録はなく、推論の大きさ・速さは変わらない。
     - 振幅で重みを付けた位相の損失 (SCNet、APNet)
     - 調波を見る判別器、または CQT 判別器
     - GAN の損失の形の変更 (SAN、または相対比較型 + R1/R2)
3. **速さは、設定で稼げる分がもうほとんど残っていない (付録 3、手元の PC で実測)**。
   - FP16 と FP32 は同じ速さだった。ORT が読み込むときに FP32 に戻すためで、FP16 で得をするのはダウンロードの大きさだけ。
   - 時間の内訳は flow 29%、text encoder 24%、decoder 30〜35%。iSTFT と PQMF は 3% 未満。
   - INT8 量子化の結果:
     - 動的量子化は約 10 倍遅くなった。
     - モデル全体の静的量子化は 22% 速くなったが、4 kHz より上が +7.4 dB 増え、雑音が足された。
     - flow だけの静的量子化は 8〜13% 速くなった。品質は正式には測っていない。
   - 大きく速くできるのは、flow を小さくすることだけ。flow はパラメータの約半分を占め、小さくするには学習し直しが要る。
   - ブラウザ版は、多スレッドに必要な cross-origin isolation の設定をしていない。そのため 1 スレッドで動いている見込みが高い。この修正は WASM 版だけで済み、音には影響しない。
   - 学習は、パディング長を決まった刻みに切り上げて cuDNN のカーネル探索を戻すと、最大 18% ほど速くなる見込み (PR #815 の固定長と可変長の差からの推測)。
4. **上の 3 つはつながっている**。flow を小さくすれば、浮いた大きさと時間を decoder に回せる (付録 1 の B、付録 3 の M1)。
5. **データ (付録 4)**。
   - 商用で使える日本語の多話者データは、Common Voice ja (CC0) と Emilia-YODAS ja (CC BY 4.0) の 2 つだけ。2026-08 に採用可と判定済み (`8caa758a`) だが、まだ学習に入れていない。
   - JVS・JSUT の無償版は非商用で使えない。

## 2. 確かめた範囲

サブエージェントの報告は、そのまま信じずに、主な主張を次のように確かめた。

| 主張 | 確かめ方 | 結果 |
|---|---|---|
| prior/flow の経路の z で decoder を学習した記録はない | `git log` と設計書の検索 | 正しい |
| 合成の方がざらつきが大きい (§7.6・§7.10) | 計画書の記録 | 正しい |
| SC-GlowTTS: TTS が予測した spectrogram で vocoder を学習し直すと、学習にいない話者の類似度が上がる | 論文の要旨 | 方向は正しい。報告にある SECS の数値 (0.764 → 0.805) は要旨になく、本文の表は確かめていない |
| SCNet (arXiv 2609.10025) の「帯域ごとの位相の損失」 | 論文の要旨 | 位相の損失は「振幅で重みを付けた位相の損失」。帯域ごとの部分は損失ではなく、条件付けのネット |
| PFluxTTS (arXiv 2602.04160) の参照の使い方 | 論文の要旨 | 音声の参照から作った埋め込みの列を使う点は正しい。報告にある数値 (0.47 → 0.57) と「学習する問い合わせ」は要旨では見えない |
| 速さの実測 (FP16・内訳・INT8) | サブエージェントが手元の PC で測った値 | 私は測り直していない。量子化した版の正式な評価 (SECS・帯域) はしていない |
| データのライセンス | 付録 4 が原文を確認 | 私は原文を見直していない |

まとめると、論文はどれも実在し、方向は報告のとおりだった。ただし、細かい数値は本文の表にあり、私が確かめたのは要旨までである。

## 3. P2′ の結果を受けて (2026-11-05 追記)

P2′ で、C (合成フィルタを固定) の 4 本から学習 seed による幅を測り直した (計画書 §7.14)。日本語 5 話者の平均での標準偏差は、CAM++ 0.036、ECAPA 0.058 だった。付録の報告は、C の 2 本の差 (ECAPA 0.094) を前提に費用と本数を見積もっている。そのため、本数の見積もりは、この新しい値で計算し直す必要がある。

K1 (帯域分割 MRD) は P2′ でも不合格だった。ただし、日本語 5 話者の平均では、K1 の 2 本がどちらも C の 4 本のどれよりも、両方の encoder で高かった。2.8 kHz より上のずれも、C のどれより小さかった (結果を見たあとの読み方なので、合否には使わない)。

ここからの方向と計画は、この調査と P2′ の結果をもとに、改めて立てる。

## 4. ユーザーが判断すること (急ぎではない)

- **moe-speech の規約の扱い**: 元の規約は「著作権法 30 条の 4 による利用のみ」。同じ規約に「学習したモデルの公開は再配布とみなさない」とあり、これを根拠に採用してきた (zs-v1 公開記録)。一方、ReazonSpeech は同じ型を理由の一つに除外していて、判断がそろっていない。「モデルの公開を規約が明示的に認めているか」で線を引けば一貫する (付録 4 §5)。P3 (データ拡充) の前に決める。
- **計画書 P3 の書き方**: 「非商用ライセンス (例: Emilia) は使わない」は、商用で使える Emilia-YODAS まで外すように読める。Emilia 本体 (CC BY-NC 4.0) に限る書き方に直したほうがよい。
- **ReazonSpeech で学習した ASR をラベル付けに使うか**: 道具の重みは Apache-2.0 / CC BY 4.0 で、ライセンス上は使える。避けるなら Whisper large-v3 (MIT) を使う (付録 4 §5)。
