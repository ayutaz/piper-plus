## 1. 結論 (推奨)

1. **zero-shot の改良だけでは、残りの予算で「本人と分かる」に届く見込みは低い** (付録 1)。
   - decoder に実録音の z を直接通す再構成でも、正規化転写率は P1 の最良の decoder で 0.51〜0.58 にとどまる (P1 設計書 §5.7)。今の最良の K1 (0.414) は、すでにその約 8 割にある。
   - 開発 5 話者では、ceiling の平均が約 0.79、floor の平均が約 0.54 (CAM++) で、幅は 0.25 しかない。
   - 小型のモデル (2,000 万パラメータ級) で、学習にいない話者を人が実録音並みに本人と判断した例は、付録 1 が調べた範囲では見つからなかった。
2. **そこで、短時間の話者適応を、目的に加える案を勧める。** 似せたい相手の録音を数十秒〜数分集め、それで短く学習し直す方式である。zero-shot は、すぐ使える入口として残す。
   - 文献では、少ない音声で似方が実録音並みになった例がある。YourTTS は 20〜61 秒の適応、VCC 2020 は約 5 分の学習データで、どちらも人の評価で確かめている (付録 1 §3.1)。
   - 重みの形は base と同じなので、大きさ・速さ・メモリは今の枠にそのまま収まる。話者ごとに ONNX を書き出せば、ランタイムの変更も要らない。
   - **これは計画書 §1 の目的 (未知の話者の参照音声から) を変える。ユーザーが決める** (§5 の D1)。
3. **zero-shot 側では、安く確かめられる候補 A を続ける** (付録 2)。
   - decoder を、推論で実際に通る経路 (text → prior → flow 逆変換) の z でも学習させる案である。
   - from-scratch の学習のあとに足す工程なので、decoder だけの学習の結果がそのまま本番の結果になる。from-scratch の比較は要らない (付録 3 §3.3)。
   - zero-shot と適応のどちらの土台も良くする。
4. **次の土台は K1 を仮に使い、確かめ直す** (付録 3 §5)。
   - P2′ では不合格だった。しかし K1 の 2 本は、日本語 5 話者の平均で、C の 4 本のどれよりも両 encoder で高かった。
   - あとから t 検定をかけると、片側 p は CAM++ 約 0.010、ECAPA 約 0.028 だった (私も同じ値を計算で確かめた)。
   - これは事前登録の外の根拠なので、K1 を新しい学習 seed で学習し直して確かめる。
   - 計画書 §6 P2′ の「不合格なら C を土台に P1 へ戻る」を変えることになる。**ユーザーが決める** (§5 の D2)。
5. **判定の規則を直す** (付録 3 §1.5・§4)。
   - 今の P2-b (A) は、効果がなくても半分以上の確率で落とす。同じレシピの C どうしでも、1 本対 1 本の比較 12 組のうち 7 組で、どれかの声に `goodhart_flag` が立った (付録 3 の再計算。記録された flag と一致)。
   - 次の比較からは、群どうしの t 検定と、群平均で見る声ごとの規則に替える (§4)。**結果を見る前に登録し、ユーザーが決める** (§5 の D3)。
6. **データ拡充 (P3) は後にする** (付録 4)。
   - 話者を足して伸びるのは、主に評価する声が足したデータと同じ種類のときである。全体ですでに 3,728 話者いるので、moe の開発群での見込みは −0.03〜+0.02 と小さい【推測】。
   - 学習 1 epoch の長さは fr で決まるので、ja を足しても学習の費用はほとんど増えない (`vits/dataset.py` の言語ごとの均等サンプリング)。
   - GPU を使わない準備 (道具、Common Voice ja のメタデータの数え上げ) は並行して進められる。

### S0 記録と事前診断 ($0、手元の CPU)

1. **計画書の記録を直す**:
   - 日本語の学習話者は「約 470」ではなく 457 (付録 4 §1.1)。
   - 学習除外話者 715 発話の件と、v10b の基準値への影響を §7.3 に注記する。

2. **候補 A の事前診断** (付録 2 §6):
   - C の decoder のまま、同じ発話を次の 4 通りで音にする。
     - (i) posterior の z
     - (ii) MAS の並び + noise 0.4
     - (iii) MAS の並び + noise 0
     - (iv) 本来の推論
   - これで、合成のずれが z の違いから来るのか、継続長から来るのかを分ける。(i) と (ii) の差が小さければ、A は効きにくいので、S1 で A を試す前に計画を見直す。
3. **判定の規則の登録** (§4 の規則の案、D3 で決まったもの)。

### S1 候補 A のふるい分け (約 $10〜40、リモートの GPU)

付録 2 §7 と付録 3 §3.4 を合わせた形にする。

- **土台**: 今ある from-scratch の 6 本 (C の 4 本、K1 の 2 本、ep40 の EMA)。
- **腕**: 次の 4 つを、同じ土台どうしの対で比べる。
  - 延長だけ (decoder を同じステップ数だけ学習し続ける)
  - A1 (推論経路の z、noise 0.4)
  - A1e (推論経路の半分には、判別器と包絡の損失だけを当てる)
  - A2 (実録音の残差を縮める)

  延長だけの腕を置くのは、「decoder を余分に学習したこと」自体の効果を差し引くためである。
- **2 段目の学習 seed による揺れ**: 候補の結果を見る前に測る。2 つの土台で、延長だけの腕を学習 seed 2 本ずつ回す。
- **評価**: 合成の経路を主にする。開発群、推論 seed 42/43/44 × 参照 2 本、`--encoder2`。再構成も測り、posterior の経路を悪くしていないことを確かめる。
- **実装**:
  - decoder だけの学習のデータに音素列を足す。手元の jsonl で、P1 の 4,776 発話はすべて発話 ID でつながる (付録 2 §1)。
  - z を作る処理は、`infer` と共通の関数として切り出す。推論の手書きの写しで配線が切れた事故 (`ca76d6ea`) と同じ型を避けるためである。
  - TDD で作る。
- **判定**: §4 の規則の案を、対にした比較に当てはめる。

## 4. 判定の規則の案 (次の比較から。事前登録の前の案)

付録 3 §4.2 の案。数値は付録 3 のシミュレーションに基づく【推測】。

- **Q-a (効果)**:
  - CAM++ と ECAPA のそれぞれで、日本語 5 話者の平均の正規化転写率について、Δ = 候補群の平均 − 対照群の平均 を出す。
  - 次の 2 つをどちらも満たせば合格とする。
    - Δ ≥ +0.03
    - 等分散を仮定した 2 群の t 検定で、片側 p < 0.10
  - 両方の encoder で合格する必要がある。
  - 効果がないのに合格してしまう率は、約 1% である。
- **Q-b (encoder を騙す方向)**: 次の 3 つをすべて満たす。
  - (1) 群平均で、CAM++ +0.02 以上かつ ECAPA +0.01 未満、の形にならない。
  - (2) `above_ceiling_flag` が、どの評価でも true でない。
  - (3) 群平均の差が CAM++ +0.05 以上かつ ECAPA −0.05 以下の声が、2 声以上ない。

  1 本対 1 本の声ごとの `goodhart_flag` は記録するが、合否には使わない。
- **Q-c (明瞭さ)**: CER の median が、候補のどの評価でも 0.30 以下。
- **Q-d (音質)**: 2.8 kHz より上のずれで、候補群の平均が対照群の平均 + 0.5 dB 以下。今の「対照群の平均以下」は、音質に効かない候補でも約半分を落とすため、幅を入れる。

この規則は P2′ の結果を見たあとに作るので、P2′ の判定 (不合格) は変えない。

## 5. ユーザーが判断すること

- **D1 話者適応を目的に入れるか**:
  - 「数十秒〜数分の録音と、短い学習で本人と分かる」を目的の内側と認めるか。
  - 認める場合、計画書 §1 と §3 を改定し、S3 を行う。
  - 認めない場合、zero-shot だけを続ける。この場合は、届かない見込みが高いことも計画書に書く。
- **D2 次の土台を K1 にするか**:
  - 計画書の規則どおり C を土台にするか。それとも、K1 を仮の土台にして S2 で確かめ直すか。
- **D3 判定の規則**: §4 の規則の案を、次の比較の事前登録に使うか。
- **D4 聴感**:
  - 適応の確認 (S3) と最終判定には、聞き分けの時間が要る。いつから聞けるか。
  - その前に、開発 5 話者で今の K1 の短い聞き分けをして、正規化転写率 0.41 が耳でどこにあるかを測るか。この測定に GPU 費用はかからない。
- **後で決めること** (P3 の前まで):
  - moe-speech の規約 (30 条の 4) の扱い。
  - 計画書 P3 の Emilia の書き方の修正。
  - 最終群の音声から声の embedding を作って、新データへの混入を調べることが、「最終判定まで使わない」に反するか。
  - 男性・年配の声や、家庭での録音を目標に含めるか。
