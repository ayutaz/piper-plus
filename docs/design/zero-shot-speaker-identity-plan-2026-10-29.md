# Zero-shot 話者再現「本人と分かる」計画 (2026-10-29)

作成日: 2026-10-29。ブランチ: `feat/zero-shot-speaker-identity`。状態: **P2 は K1・F とも不合格 (§7.12)。C を 2 本足して判定し直した P2′ でも K1 は不合格 (§7.14)。次の方向と計画は [zero-shot-next-direction-2026-11-05.md](zero-shot-next-direction-2026-11-05.md)。話者適応を目的に加え、K1 を仮の土台にして確かめ直す (§6 の 2026-11-05 の改定)。いまは開発群で K1 の聞き分け (P0-4′) を行っている** (2026-11-05。P0 は P0-4/5 の較正と T・N4 の確定が残る)。

## 1. 目的と前提

未知の話者の参照音声から合成した声が、**聞いて本人と分かる**水準になることを目的とする。
「別人には聞こえない」程度では目的を満たさない。

ユーザーが決めた前提 (2026-10-28〜29):

| 項目 | 内容 |
|---|---|
| 目標 | 「本人と分かる」 (§3 の判定規則で判定する) |
| モデルサイズ | TTS 本体の FP16 ONNX は v10b ep79 の正式版 (40,763,422 バイト) より大きくしない。参照音声側は今の `campplus.onnx` のままにし、別の encoder を足さない (2026-10-29 改定。改定前は「FP16 で 40MB 以内、参照 encoder は CAM++ と同程度 (約 4MB) 以内」で、実物の `campplus.onnx` は 28,303,423 バイトと記載が食い違っていた) |
| 速度とメモリ | CPU 推論 p50 と推論時のメモリは v10b ep79 とほぼ同じ (どちらも 1.03 倍以下、測り方は §6 P2-f) (2026-10-29 改定。改定前は速度 +10% 以内) |
| 聞き手 | ユーザー 1 名 |
| データ | これまでと同じく商用利用可のデータだけを使う (非商用ライセンスのデータは使わない) |
| GPU 予算 | CloudRift と vast.ai で合計 $1000 まで。予算内で精度を上げ切る |

出発点 (調査済み、2026-10-28):

- 現行の最良は v10b ep79。参照融合計画 ([zero-shot-reference-fusion-plan-2026-10-17.md](zero-shot-reference-fusion-plan-2026-10-17.md)) の候補はすべて不合格だった。
- 学習に使っていない日本語話者で見ると、cross-utt の類似度は 0.60 前後で頭打ちになっている。つくよみ (学習外の別録音) は 0.72〜0.75 で、日本語女性の floor 0.70〜0.74 とほぼ同じ。正規化転写率は 0.2〜0.35。
- 話者情報の損失の 78% は decoder 段で起きている。recon bound は 0.714 で、decoder より手前をいくら改善しても上限は +0.04。FiLM の scale は sigmoid の上限 0.4998 に張り付いている。
- 過去の調査 ([zero-shot-v10-similarity-research.md](zero-shot-v10-similarity-research.md)) では、192 次元のベクトル 1 本で話者を伝える方式の転写率は 0.5〜0.6 が上限。実音声並みの類似度が出るのは、参照音声の系列そのものをモデルに見せる方式だけだった。
- 日本語の学習データには、moe-speech-plus の約 470 話者 (学習除外 10 話者を除く) がすでに入っている (2026-11-05 訂正: P2 の学習データ 299,728 発話で数えると 457 話者・53,202 発話。[次の方向の付録 4](zero-shot-next-direction-2026-11-05/data-plan.md) §1.1)。学習していない日本語話者でも 0.60 で頭打ちのため、話者数より方式が律速とみる。

## 3. 最終判定規則 (事前登録)

最終判定は P4 のモデルに対して 1 回だけ行う。判定には**最終群**を使う。最終群は学習除外の日本語 5 話者 (11b1eb07、1cc3c6c0、23e5ef98、3d995663、46f336bf) とつくよみで、最終判定まで聴感でも数値でも使わない。つくよみは開発中にも数値評価で使ってきたため、聴感試験の最終群にだけ入れる。

判定は 2 段に分けて報告する。

- **合格**: 学習除外 5 話者とつくよみのどちらでも、L1〜L3 と N1〜N5 をすべて満たす。
- **部分合格**: 学習除外 5 話者では満たすが、つくよみで満たさない。

### 3.1 聴感 (主判定)

聞き手はユーザー 1 名。試験形式は §5 に従う。各試行では、話者 S の実録音 (参照) を聞いた後に試験音声を聞き、「同じ人か」を 4 段階で答える (確実に別人 / たぶん別人 / たぶん本人 / 確実に本人)。「たぶん本人」と「確実に本人」を「本人」と数える。

試験音声の条件:

| 記号 | 試験音声 | 意味 |
|---|---|---|
| R+ | S の別の実録音 | 聞き手にとっての上限 |
| R− | S と同性で声の近い別話者の実録音 | 聞き手が別人を本人と誤る率 |
| Z+ | S の参照から合成した音声 (参照とは別の文) | 合成が本人に聞こえるか |
| Z− | 別話者 S′ の参照から合成した音声 | 合成が「誰にでも似た声」になっていないか |

`H(x)` は条件 x で「本人」と答えた率とする。条件ごとに 48 試行 (6 声 × 8)。

| 規則 | 内容 |
|---|---|
| L1 | `H(Z+) ≥ 0.75` (48 試行中 36 以上) |
| L2 | `H(Z+) ≥ H(R+) − 0.15` |
| L3 | `H(Z−) ≤ H(R−) + 0.10` |
| L0 (試験の有効性) | 同じ試行を伏せて繰り返した組で、答えが一致した率が 0.8 以上。満たさないセッションは無効とし、日を改めてやり直す |

### 3.2 数値 (補助判定)

| 規則 | 内容 |
|---|---|
| N1 | CAM++ と ECAPA の両方で、正規化転写率が閾値 T 以上。T は P0-5 の規則で決め、P0 の完了時に確定する。確定までの仮の値は 0.6 |
| N2 | `goodhart_flag` と `above_ceiling_flag` がどちらも true でない (`--baseline-json` は v10b ep79) |
| N3 | CER の median が 0.30 以下 ([zs-eval-contract.md](../spec/zs-eval-contract.md) §7) |
| N4 | 音質の規則 (契約 §6)。P0-6 で comb 指標を差し替える場合は、新しい名前で P0 の完了時に登録し直す |
| N5 | §1 の大きさ・速度・メモリの前提を満たす (具体的な測り方と閾値は §6 P2-f と同じ。2026-10-29 改定、改定前は「FP16 で 40MB 以内、参照 encoder が約 4MB 以内、CPU p50 が +10% 以内」) |

判定規則は P0 の完了コミット以後は変えない。変える必要が出た場合は、新しい規則として別名で登録し直し、古い規則での結果も併記する ([zero-shot-noise-root-cause-pqmf.md](zero-shot-noise-root-cause-pqmf.md) §4 の再発防止)。

## 4. P0: 判定基準と測定系

目的: これまでの判定は日本語 5 話者・seed 1 つで、ノイズ指標 (comb 超過) が聴感上のノイズと対応しているかも確かめていなかった。S5′ の不合格もこの comb 超過によるものだった。測り方を先に固め、改善とばらつきを区別できるようにする。

使う資源: ローカルの CPU と RTX 4070 Ti SUPER。GPU のレンタルはしない。

| 作業 | 内容 | 完了条件 |
|---|---|---|
| P0-1 評価音声の取り直し | 学習除外の 10 話者の音声を HF `ayousanz/moe-speech-plus` から取り直す (話者ごとの zip のみ)。つくよみはローカルの `datasets/tsukuyomi-raw/wavs` を使う | 開発 5 話者の参照 wav の sha256 が S4 の manifest (`/data/piper/eval-s4/set/groups/*/speaker/*.wav`) の記録と一致する。一致しない場合は差を記録し、新しいセットとして扱う |
| P0-2 評価セットの固定 | 開発群 (5 話者 + つくよみ) の参照・実発話・floor 話者・文を manifest に固定する。最終群は一覧だけ作り、音声は合成も試聴もしない | manifest と作成スクリプトをコミットする |
| P0-3 v10b の基準値 | v10b ep79 (HF `checkpoints-v10b/epoch=79-step=106880.ckpt`) を、推論 seed 3 つ × 参照 2 本で評価する | 指標ごとに平均と、seed・参照の違いによる幅を記録する |
| P0-4 聴感試験の道具と較正 | §5 の試験を作る道具と集計の道具を TDD で作る。開発群で、R+ / R− / Z+ (v10b) / Z− (v10b) の較正セッションをユーザーが行う | `H(R+)`、`H(R−)`、v10b の `H(Z+)`・`H(Z−)` と L0 を記録する |
| P0-5 数値と聴感の対応 | 較正セッションの答えと、同じ試験音声の SECS を照らし合わせる | T を次の規則で決める: 較正で「本人」と答えた Z+ 試験音声の正規化転写率の中央値と 0.6 のうち、大きい方。Z+ で「本人」が 5 件未満なら 0.6 とする |
| P0-6 comb 指標の確認 | 実録音と合成音声で comb 超過の分布を出し、推論 seed による幅を測る。S5′ の C0 ep39 と C0-self ep39 の音声を伏せて聞き比べ、ノイズの多い方を選ぶ試験を行う (20 組) | 次のどちらかを記録する: comb 指標を続けて使う (聞き比べで comb 超過の大きい方を選んだ率が 0.7 以上)、または差し替える (新指標を別名で登録する) |
| P0-7 decoder 段の診断 | v10b ep79 と S5′ の ckpt で、話者情報が decoder のどの層で失われるかを測る。層ごとの FiLM scale の張り付きも調べる | 損失の大きい層と、その量を記録する。P1 の注入先の根拠にする |
| P0-8 pt `ã` の確認 | `ã` (U+00E3) が音素 ID 表になく、学習・推論の両方で黙って落ちているかを確かめる | 落ちていれば、P4 の学習データを作る前に直す方針 (ID 追加とランタイムへの影響) を記録する |

P0 の完了条件: P0-1〜P0-8 の完了条件をすべて満たし、T と N4 の扱いを確定させた版の本書をコミットする。

## 5. 聴感試験の形式

- 試験はブラウザで開く静的な HTML とし、音声と一緒にローカルに置く。答えは JSON で保存する。
- 試行の順番は乱数で決め、条件・話者・モデル名はファイル名からも分からないようにする (ハッシュ名にする)。
- 合成音声は参照とは別の文にする。実録音も、参照とは別の発話を使う。
- 聞きやすさを揃えるため、すべての試験音声に同じ音量の正規化をかける (実録音も同じ)。数値の測定は契約 §2-5 に従い、正規化前の素の出力で行う。
- 1 セッションの 10% の試行を、伏せたまま繰り返す (L0 の確認用)。
- 1 セッションは 40 分以内とする。それより長くなる場合は日を分ける。
- 道具は判定の閾値を持たない。集計の道具が出した率を、本書の規則に照らして人が判定する。

## 6. P1 以降の概要

### P1 方式設計

- 参照音声を短い特徴の列 (数十フレーム程度) に変え、decoder がそれを cross-attention で参照する方式を主候補とする。注入先は P0-7 の結果で決める。
- 参照音声の処理は話者ごとに 1 回で済ませ、結果を使い回せる形にする。こうすると、1 発話あたりに増える計算は decoder 内の参照だけになる。
- 小さな変更の候補として、FiLM の上限を外す方式 (`--film-free-scale`) を単独で試す。v11 の中でしか試しておらず、単独の効果は確かめていないため、P2 の比較群に入れる。
- 固定 encoder の点数を学習の目標にしない ([zs-eval-contract.md](../spec/zs-eval-contract.md) §2-4)。
- ゴール: 試作 ONNX (重みはランダム) で N5 を実測する。6 ランタイムの変更範囲を見積もる。P2 の比較群・epoch 数・seed 数・合格条件を事前登録する。

### P2 小規模比較

- warm restart では判断しない (v9 の 7 介入で、warm restart では転写能力が戻らないと確定済み)。全群を from-scratch で、同じデータ・同じ epoch で学習する。
- 対照群 (現行方式) を seed 違いで 2 本以上学習し、学習のやり直しによる指標の幅を測る。G5′ で分からなかった「comb 超過の run 間のばらつき」もここで測る。
- 合格の目安 (P1 の終わりに確定する): 開発群の正規化転写率が、両方の encoder で対照の平均を学習のやり直しによる幅の 2 倍を超えて上回る。N2〜N4 で悪化しない。開発群の聴感で `H(Z+)` が上がる。

#### P2 の事前登録 (2026-10-29 登録)

P2 の学習を始める前に、以下を変えずに使う。変える必要が出た場合は、§3 と同じく別名で登録し直し、古い規則での結果も併記する。

比較群 (すべて from-scratch、v10b と同じ学習データ、同じ 40 epoch):

| 記号 | 内容 | seed 数 |
|---|---|---|
| C | 対照。v10b のレシピそのまま | 2 |
| K1 | P1 の decoder 比較 ([P1 decoder 設計](zero-shot-decoder-p1-design-2026-10-29.md) §5) で勝った decoder の構成。v10b の大きさに収めるための flow の縮小を含む (D5 なら段数 4 → 2、D2〜D4 なら 4 → 3。D0/D1 なら縮小なし。設計書 §7.4) | 2 |
| K2 | K1 + 参照 cross-attention。参照の特徴は、別の encoder を足さずに CAM++ の統計 pooling 直前の時間ごとの特徴を `campplus.onnx` の 2 つ目の出力として取り出す。P1 の decoder 比較で、話者の条件付けを強めると再構成の話者の保ち方が上がった場合だけ入れる | 2 |
| F | C + `--film-free-scale` のみ (§6 P1 の小さな変更の単独効果) | 1 |
| Cf | C + K1 と同じ flow の縮小のみ (decoder は v10b のまま)。K1 が flow の縮小を含まない (D0/D1) なら学習しない。K1 の差を decoder と flow に分けるための群で、次の P2-g の判定に使う | 1 |

K1 の具体的な構成は、P1 の decoder 比較の結果を記録したコミットで本表に書き足し、その後は変えない。

**K1 の構成 (2026-10-30 確定)**: D0。v10b と同じ decoder の形のまま、合成フィルタ (PQMF) を本来の形に固定し、帯域分割 MRD を足す。flow は 4 段のまま縮めないので、Cf は学習しない。P1 では D0 が数値の判定 (a)〜(c) と聞き比べ (d) (10 組中 10) のすべてに合格した (P1 設計書 §5.7・§5.8)。D2-32 (n_fft 32、flow 3 段が前提) も全部に合格し数値では D0 を上回ったが、P1 設計書 §5.6 の決まりにより K1 には D0 を使い、D2-32 は P2 で足りなかったときの次の手にする。

評価: 各 run の ep40 の EMA を、開発群 (日本語 5 話者 + つくよみ) で、推論 seed 3 つ × 参照 2 本で測る (P0-3 と同じ手順、`/eval-zs`、`--encoder2` あり)。

合格条件 (K1・K2・F のそれぞれを C と比べる。すべてを満たしたら合格):

| 規則 | 内容 |
|---|---|
| P2-a | CAM++ と ECAPA の両方で、正規化転写率 (日本語 5 話者の平均) の候補の seed 平均が、C の seed 平均を `max(2 × |C の 2 seed の差|, 0.05)` より大きく上回る。0.05 は、推論 seed だけによる 5 話者平均の振れ幅 (CAM++ 0.026、ECAPA 0.030、§7.3) の約 2 倍 |
| P2-b | `goodhart_flag` と `above_ceiling_flag` がどちらも true でない (`--baseline-json` は C の 1 本目) |
| P2-c | CER の median が 0.30 以下 (N3) |
| P2-d | 音質: 2.8 kHz より上の 500 Hz ごとのエネルギーの割合の、同じ声の実録音との差の絶対値の平均 (§7.9 の候補指標) が、C の seed 平均以下。さらに K1 は、伏せた聞き比べ (C と K1 の同じ文、20 組) で C をざらつく方に選んだ率が 0.7 以上 (P0-6 と同じ基準) |
| P2-e | 聴感: 開発群の聞き分け (Z+ を候補と C で各 24 試行、10% を伏せて繰り返す) で、`H(Z+)` が C より 0.15 以上高い。L0 を満たさないセッションは無効とし、やり直す |
| P2-f | N5: FP16 ONNX が v10b ep79 の正式版 (40,763,422 バイト) 以下で、参照側の ONNX は `campplus.onnx` 以外を足さない。`piper_train.tools.measure_variant_cost --memory-repeats 3` で v10b ep79 の正式な ONNX と同じ回の測定に入れ、(1) 3 つの入力の p50 の合計が正式版の 1.03 倍以下、(2) モデルの読み込みと推論によるピークの作業セットの増分 (3 回の中央値) が正式版の 1.03 倍以下 |

改定 (2026-10-29): 当初は「40 MiB 以内、速さ 1.10 倍以内」で登録したが、P2 の学習を始める前に、ユーザーの指示「すでにあるものとサイズが変わらずに処理速度やメモリがほぼ変わらない範囲で進める」で上の P2-f に改め、P2-g を加えた。1.03 倍は、同じ回の測定で中身が同じ ONNX どうしの差 (速さ 1.4%、メモリ 0.5%、3 回のメモリの幅 1.4%) の約 2 倍 (設計書 §7.4)。

改定 (2026-10-30、P2 の学習を始める前、P1 の結果と §7.10 の差し替えの確認を受けて):

- **C の合成フィルタ**: v10b は合成フィルタを学習で動かした (`trainable_pqmf_synthesis: True`) が、C は今の既定どおり**本来の形に固定**して学習する (ユーザーの判断)。K1 との違いは帯域分割 MRD だけになり、P1 の 2 つの直し方のうち MRD の効果を分けて見られる。動くフィルタは §7.9 のとおり本来の形から大きくずれて往復の SNR が 7.6 dB まで壊れており、対照として再現する意味が薄い。v10b ep79 そのものとの比較は、§7.3 の基準値と並べて参考に記録するだけで、合否には使わない。
- **K2 は学習しない**: K2 を入れる条件 (P1 で話者の条件付けを強めると再構成の話者の保ち方が上がること) を、P1 の decoder 比較では試していない。参照 cross-attention は、P2 の結果を見てから次の比較で扱う。
- **Cf は学習しない** (K1 = D0 は flow を縮めない)。P2-g は課さない。
- **P2-d の聞き比べ**: 20 組・率 0.7 以上を、**10 組・8 以上** (C をざらつく方に選んだ数) に改める。偶然で 8 以上になる確率は 56/1024 ≈ 0.055 で、20 組で 14 以上 (≈ 0.058) とほぼ同じ。聞き手の負担を減らすため (P1 設計書 §5.6 と同じ改定)。組の作り方は、開発群 6 声から声ごとに 2・2・2・2・1・1 組、K1 が A になる組と B になる組を 5 組ずつにする。数値の部分 (2.8 kHz より上のずれが C の seed 平均以下) は変えない。
- **学習する run**: C ×2、K1 ×2、F ×1 の 5 本。K1 の帯域分割 MRD は今は decoder だけの学習の道具 (`tools/train_decoder_only.py`) にしかないので、全体の学習 (`vits/lightning.py`) に opt-in のフラグとして足してから学習する。費用の見積もりは 5 本で約 $60〜80。

判断:

- K1 が合格したら、K1 を P4 のレシピにする。K2 が合格し、さらに P2-a の差が K1 より同じ幅を超えて大きければ、参照 cross-attention も P4 に入れる。
- どの候補も不合格なら、理由を本書に記録して P1 に戻る。
- 学習中の停止条件: 既存の安全装置 (KL の上限への張り付き、non-finite) に加えて、ep20 の CER median が 0.6 を超えた run は止める (v11 の較正: 明瞭 0.095、不明瞭 1.43)。

費用の見積もり: CloudRift の RTX 5090 で 80 epoch が約 36 時間・約 $23 なので、40 epoch は約 $12。decoder が大きい群は学習が遅くなる分を 1.5 倍とみて約 $18。8 本で約 $120、評価と立ち上げの余裕を入れても配分の $300 に収まる。

P1 の試作の測定 ([P1 decoder 設計](zero-shot-decoder-p1-design-2026-10-29.md) §7.4) で、N5 に収まる構成と収まらない構成が分かった。flow を縮めずに収まるのは D0/D1 だけで、D2〜D4 と cross-attention は flow 段数 3、D5 は段数 2 と組み合わせれば収まる。K1・K2 の構成は、この表で N5 に収まるものから選ぶ。

#### P2′ C を足しての判定のやり直し (2026-11-02 登録、追加の学習を始める前)

P2 は K1・F とも不合格だった (§7.12)。K1 が届かなかった主な理由は、C の 2 本の学習 seed による差 (ECAPA 0.094) で P2-a の幅が 0.187 まで広がったことにある。ユーザーの判断で、C を 2 本足して学習 seed による幅を測り直し、K1 を次の規則で判定し直す。**この規則は P2 の結果を見たあとで決めた**。P2 の規則での不合格は §7.12 のとおり残し、P2′ で合格しても P2 より弱い根拠として扱う。

追加の学習: C-s1236・C-s1237。コード `8a011b1a`、学習の引数は C-s1234 と seed・出力先以外同じ。GPU は P2 と同じ L40S で 1 GPU に 1 run。評価は §6 P2 と同じ手順 (ep40 の EMA、開発群、推論 seed 42/43/44 × 参照 2 本、`--encoder2`、`--baseline` は C-s1234)。K1 は P2 の 2 本 (K1-s1234・K1-s1235) をそのまま使う。

以下で「run の値」は、推論 seed 3 つの平均。C の平均と標準偏差 (n−1 で割る) は C の 4 本 (s1234〜s1237) の run の値から求める。

| 規則 | 内容 |
|---|---|
| P2′-a | CAM++ と ECAPA の両方で、正規化転写率 (日本語 5 話者の平均) の K1 の 2 本の平均が、C の 4 本の平均を `max(2 × C の 4 本の標準偏差, 0.05)` より大きく上回る。参考: 今の C の 2 本だけで計算すると幅は CAM++ 0.068、ECAPA 0.133 で、K1 の差 (ECAPA +0.082) はこれに届かない |
| P2′-b | 次の 2 案を登録する。どちらを使うかは、追加の 2 本の評価が出る前にユーザーが決める。決まらなければ A を使い、B の結果は参考として並べる。**A**: P2-b のまま (声ごとの `goodhart_flag` と `above_ceiling_flag` が、C-s1234 との比較で 1 つも true でない)。K1 は P2 ですでにこの規則を満たしていない。**B**: (1) 日本語 5 話者の平均で、K1 の 2 本の平均の C の 4 本の平均に対する差が、CAM++ +0.02 以上かつ ECAPA +0.01 未満にならない。(2) `above_ceiling_flag` が K1 のどの評価でも true でない。(3) 声ごとに、K1 の 2 本の平均の CAM++ が C の 4 本のどれよりも高く、かつ ECAPA が C の 4 本のどれよりも低い声がない。B の理由: レシピが同じ C どうし (C-s1235 対 C-s1234) でも、つくよみで推論 seed 3 つすべてに `goodhart_flag` が立った。声ごとに 1 本だけと比べる形では、学習のやり直しによる幅だけで印が立つ |
| P2′-c | CER の median が、K1 のどの評価でも 0.30 以下 (P2-c と同じ) |
| P2′-d | 2.8 kHz より上のずれ (§6 P2-d と同じ指標) の K1 の 2 本の平均が、C の 4 本の平均以下。さらに、伏せた聞き比べ 10 組で C をざらつく方に選んだ数が 8 以上。組は K1-s1234 対 C-s1234 を 5 組、K1-s1235 対 C-s1235 を 5 組、推論 seed 42、同じ声・同じ文・同じ参照。声ごとの組数は開発群 6 声で 2・2・2・2・1・1、K1 が A になる組と B になる組を 5 組ずつ |
| P2-e・P2-f | 変えない。P2-f は追加の学習の間に手元の CPU で測る。P2-e は P0-4/5 の較正が済んでから行う |

判断: P2′-a〜d を満たし、P2-e・P2-f も満たせば、K1 を P4 のレシピにする (§6 P2 の判断と同じ)。満たさなければ、C (合成フィルタを固定) を土台にして P1 に戻り、次の候補を設計する。どちらの場合も、C の 4 本で測った学習 seed による幅を、次の比較で 1 群に何本学習するかを決めるのに使う。

改定 (2026-11-02、追加の学習を始める前): ユーザーの判断で、P2′ では耳で聞く試験をしない。P2′-d は数値の部分 (2.8 kHz より上のずれが C の 4 本の平均以下) だけにし、聞き比べ 10 組 (公開済みのページ) は判定に使わない。P2-e も行わない。K1 の合格は P2′-a〜c、P2′-d の数値の部分、P2-f (§7.12 で合格済み) で決める。数値で良くても耳では違いが分からない、という失敗は、P4 の後の最終判定 (§3.1) まで見つからない。

運用 (ユーザーが確認できない間の決まり): 2 本の費用の見込みが $90 以下のときだけ借りる。温まってから測った速さで見込みが $90 を超えたら、terminate して相談する。L40S 以外の GPU には替えない。ep20 の CER median が 0.6 を超えた run は止める。改定 (2026-11-02、学習の開始後): ユーザーの指示で、この上限を $90 から $100 に上げる (温まってからの速さによる見込みは約 $80 で、改定前の上限にも収まっていた)。

P0-4′ K1 による聞き分けの較正 (2026-11-05 登録、答えを集める前):

- 目的: 今の K1 (正規化転写率 0.41) が耳でどこにあるかを測り、§4 の P0-4・P0-5 を K1 で行う。P0-4 の v10b の較正セッション (c1〜c11) は雑音のため止まっていて (§7.8)、行わない。

S0 候補 A の事前診断 (2026-11-05 登録、音を作る前):

- 目的: 次の方向の文書 §3 S0 の 2。合成のずれが「z の分布の違い」と「継続長」のどちらから来るかを分け、候補 A (decoder を推論経路の z でも学習させる) が効く余地があるかを、学習の前に見る。合否ではなく、S1 に進むかどうかの判断に使う。
- 材料: moe-speech-plus の学習話者のうち、P1 の 48 名と開発群・最終群を除いた 6 名 (`diagnose_prior_path pick-speakers --seed 20261105` で選んだ 20b5dff7、297efce1、2fbfe282、c593ed00、de45b781、fada1cbf)。1 名あたり参照 1・合成する発話 10・cross 用の実発話 10 (2〜12 秒、`prepare --seed 20261105`)。floor は他の 5 名の cross から 2 発話ずつ。C の学習に入っていた話者なので、学習外の話者の評価ではなく、経路の差を見る診断である。
- 土台: C-s1234 と C-s1235 の ep40 EMA。
- 4 通り (`diagnose_prior_path generate --seed 42`): (i) posterior の z、(ii) MAS の並び + noise 0.4、(iii) MAS の並び + noise 0、(iv) 継続長予測による本来の推論 (scales 0.4/1.0/0.5)。(i)〜(iii) は同じ posterior の標本から作る。z の作り方は、学習・推論と同じ部品を通す `SynthesizerTrn.prior_path_latent` (forward・infer と出力が一致することをテストで固定)。
- 測るもの: 正規化転写率 (CAM++・ECAPA、`run_zs_eval_set`)、2.8 kHz より上のずれ (`measure_highband_deviation`、同じ話者の cross の実発話と比べる)、comb-HNR、CER median、σ_r。
- 読み方 (2 土台の平均で、差 d_z = (ii) − (i)、d_dur = (iv) − (ii)):
  - **A が効く余地がある**: 高域のずれの d_z が +0.5 dB 以上、または正規化転写率の d_z が両 encoder とも −0.05 以下。
  - **A は効きにくい (S1 の前に計画を見直す)**: 高域のずれの |d_z| が 0.5 dB 未満、かつ正規化転写率の |d_z| が両 encoder とも 0.05 未満、かつ同じ指標で |d_dur| が |d_z| より大きい。
  - どちらでもない: S1 に進むが、その旨を記録する。
  - 0.5 dB は Q-d の幅、0.05 は decoder だけの学習の同じ構成の中の広がり (§7.10、CAM++ 0.03・ECAPA 0.04〜0.06) に合わせた。
  - σ_r は A2 の λ (= 0.4/σ_r) を決めるのに使う。

- G5′ を不合格にした comb 超過の差 (C0 2.74 dB 対 C0-self 1.68 dB) は、合成時の振れ幅 (0.24 dB) の 4 倍以上ある。合成の乱数では説明できない。学習のやり直しによる幅は P2 で測る。
- つくよみ 1 声だけの値は 0.09〜0.16 動く。これまでの「つくよみで +0.03」のような結論は、振れ幅の中にある。
- P2 以降の比較では、seed 3 つ以上の合成をまとめて評価する。差の判定には、この節の振れ幅と、P2 で測る学習のやり直しによる幅を使う。

注記 (2026-11-05): v10b を含む v9〜v11 は「v9 と同じ 300,443 発話」で学習したと記録されている (`docs/design/zero-shot-v11-roadmap.md`)。HF から回収した v9 の jsonl には、学習除外 10 話者のうち 6 話者・715 発話 (開発群の 361eb7a2・673810f3・6e22f5cd と、最終群の 3 話者) が入っている (`docs/handoff/zero-shot-cpu-to-gpu-2026-10-17.md:25`)。回収物が学習の実体と同じかは確かめられていないが、v10b ep79 がこの 3 声を学習で見た可能性がある。そのため、この節の v10b の基準値の日本語 5 話者の平均は、学習で見た声を含むかもしれない。v10b との比較は合否に使っていない (§6 P2 の改定)。P2 以降の学習データ (299,728 発話) はこの 715 発話を除いた版で、S2 の監査で重複 0 を確かめている。v10b ep79 は最終群で評価しない。

### 7.4 P0-4 聴感試験 (2026-10-29、道具は完了、較正セッションは未実施)

### 7.6 P0-7 decoder 段の再構成 (2026-10-29、v10b EMA で完了)

方法 (`python -m piper_train.tools.measure_recon_bound`): 各群の実発話 10 本を、評価セットの cross 用とは別に選んだ (moe-speech-plus は 3〜10 秒を path 順に、評価セットとの sha256 重複なし。つくよみは VOICEACTRESS100_011〜020)。学習と同じ前処理 (`cache_norm_audio_fast`) で spec にし、`enc_q` → decoder に直接通した (prior・flow・duration は通らない)。

- own: `enc_q` も decoder も、その群の参照 (ref0) の g。
- swap: `enc_q` はその群の g、decoder だけ別の群の g (開発話者を順に入れ替え、つくよみには 361eb7a2)。

正規化転写率 (`eval_zs_secs`、TTS は seed 3 つの平均):

| 群 | CAM++ TTS | CAM++ own | CAM++ swap→元話者 | ECAPA TTS | ECAPA own | ECAPA swap→元話者 |
|---|---|---|---|---|---|---|
| 日本語 5 話者の平均 | 0.245 | 0.297 | 0.115 | 0.224 | 0.061 | −0.023 |
| つくよみ | 0.199 | 0.260 | 0.273 | 0.113 | 0.380 | 0.377 |

再構成が元の発話をどれだけ保つか (CAM++ cosine の平均):

| 群 | 再構成 ↔ 元の発話 | 元の発話 ↔ 同じ話者の別の発話 (cross) | 再構成 ↔ cross |
|---|---|---|---|
| 361eb7a2 | 0.681 | 0.753 | 0.657 |
| 673810f3 | 0.621 | 0.700 | 0.621 |
| 6b2b26d1 | 0.654 | 0.747 | 0.594 |
| 6e22f5cd | 0.627 | 0.696 | 0.542 |
| 75e27ad3 | 0.734 | 0.770 | 0.661 |
| つくよみ | 0.744 | 0.866 | 0.714 |

読み取り:

- つくよみの own の cross-utt SECS は 0.714 で、v11 設計 §10.1 の recon bound (0.714) と一致した。
- **実音声を事後エンコーダー → decoder に通して戻すだけで、元の発話との類似度は 0.62〜0.74 まで落ちる。** これは「同じ人の別の発話」との類似度 (0.70〜0.87) より低い。decoder は、正しい潜在表現を受け取っても入力の声を描き直せていない。話し方のずれでは説明できない。
- 上流 (prior・flow・参照の条件付け) をどれだけ改善しても、正規化転写率は own の水準 (CAM++ で約 0.3) を大きくは超えない。§3 の目標 (仮の T = 0.6) には、**decoder の描き直しの忠実さを上げることが必須**。P1 の主な対象は decoder とする。
- swap では、decoder の g を替えると元の話者から離れる (日本語 CAM++ 0.297 → 0.115) が、decoder 側の話者には近づかない (CAM++ 0.136、ECAPA −0.185)。つくよみでは decoder の g を替えてもほぼ変わらない。decoder の条件付けは声の主を「描き分ける」働きをしていない。
- comb 超過は own では日本語 0.69 dB、つくよみ 0.82 dB (実録音 0.81 dB) で、実録音並み。TTS の約 2.0 dB は、decoder 単体ではなく、prior から作った潜在表現を decoder に入れたときに出る。
- 制約: 日本語の ECAPA own が TTS より低い群がある (361eb7a2 −0.29 など)。CAM++ と ECAPA で向きが違うため、ECAPA 単独の own の値は判断に使わない。torch-raw では未測定。

### 7.7 P0-6 comb 指標の聞き比べ (2026-10-29、ページは完成、試聴は未実施)

- 道具: `python -m piper_train.tools.listening_noise_ab build / score`。
- 材料: S5′ の C0 ep39 と C0-self ep39 の torch-ema 合成 (各 72 clip、同じ文・同じ参照)。同じ clip どうしで comb 超過を比べると、C0 の方が大きい clip が 65/72、差の平均は +0.97 dB だった。
- 組の選び方: 差が 0.67 dB (7.3 の話者 1 人あたりの振れ幅の最大) 未満の組は除いた。指標の上で C0-self の方が雑音が多い組 (−1.26 / −0.83 dB) は 2 組とも入れた。モデルの違いそのものを雑音と取り違えても、指標と一致して見えないようにするため。残りの 18 組は seed 20261029 で無作為に選び、1 声あたり 4 組までにした。差は 0.83〜2.29 dB。
- 20 組に繰り返し 2 組を足した。comb の大きい方が A に来る組は 10 組。音量は RMS だけ揃え、帯域は変えていない。
- 判定 (P0 の表の規則): 繰り返しを除く 20 組で、comb 超過の大きい方を「雑音が多い」と選んだ率が 0.7 以上なら comb 指標を続けて使う。0.7 未満なら、N4 の指標を差し替える案を P0 の完了時に別名で登録する。
- 結果 (2026-10-29、聞き手 1 名): **comb 超過と一致 10/20 = 0.50 (Wilson 95% 0.30〜0.70)**。7.8 の後で追加した comb-HNR とも 8/20 = 0.40 (0.22〜0.61) で、どちらも偶然と区別できない。2 つの指標の向きが逆の 12 組では、comb 超過と一致 7、comb-HNR と一致 5 (comb-HNR の差が 1 dB 以上の 7 組では 4 対 3)。繰り返しの 2 組は 2 組とも同じ答えだった。C0 を選んだのは 12/20。聞き手の所見は「A も B も雑音が多い組がある」。
- 判定: comb 超過は規則の 0.7 に届かず、**N4 の指標を差し替える**。comb-HNR も、雑音の多いモデルどうしの細かい差では聴感と合わなかった。一方、実録音と再構成・合成の大きな差 (7.8) は comb-HNR に出ている。指標が「どれだけの差から聞き分けに対応するか」は未確定で、差し替える指標は、雑音の量がはっきり違う組で聴感と照らしてから登録する。

### 7.8 聞き分けの較正の中断と、decoder の雑音 (2026-10-29)

聞き分けの較正の 1 回目 (c1) は 13 試行で止めた。本人の別の実録音は 1/1、別人の実録音は 0/4 で「本人」と答え、実録音は正しく聞き分けられた。一方、合成は本人の参照から作ったものも 0/5 で、すべて「別人」と答えた。聞き手の所見は「合成はガビガビで、全然違う音に聞こえる」。合成の雑音が判断を支配するので、この状態では数値と聴感を対応させる較正 (P0-5) ができない。c2〜c11 は実施せず、雑音が聞き分けの邪魔にならないモデルができてから較正をやり直す。

雑音がどの段階で入るかを、声ごとに実録音・再構成 (7.6)・合成を並べて聞いた (伏せない試聴、各 1 発話)。試聴用の加工の前後で、comb 超過は変わらなかった。

| 声 | comb-HNR 実録音 / 再構成 / 合成 (dB、大きいほど調波がきれい) | comb 超過 実録音 / 再構成 / 合成 (dB) |
|---|---|---|
| 361eb7a2 | 14.0 / 8.0 / 8.7 | 0.30 / 0.82 / 4.02 |
| 673810f3 | 12.2 / 5.3 / 6.3 | 0.57 / −0.33 / 1.48 |
| 6b2b26d1 | 13.9 / 7.8 / 6.6 | 1.14 / −0.17 / 1.35 |
| 6e22f5cd | 7.1 / 4.2 / 0.8 | 0.82 / 0.55 / 3.48 |
| 75e27ad3 | 6.8 / 5.3 / 5.4 | 0.71 / 1.24 / 2.02 |
| つくよみ | 13.0 / 5.8 / 9.5 | 0.30 / 1.11 / 3.00 |

- 聞き手の所見: **再構成もガビガビ**。361eb7a2 の再構成がいちばんひどく、ほかの再構成もガビガビだが、まだまし。
- comb-HNR (1〜3kHz の調波の間の雑音) では、再構成は実録音より 1.5〜7 dB 低く、雑音が聞こえるという所見と合う。この発見は v10b 残存ノイズ診断 §8 (再構成 6.71 dB、乱数なしの平均値 m_q でも 5.73 dB) と同じで、今回 6 声で確かめた。
- comb 超過 (4kHz より上の格子状の雑音) は、再構成では実録音並みで、聞こえる雑音を捉えていない。現在の N4 (契約 §6 の comb 超過) だけでは、この雑音を見逃す。
- どちらの指標も、361eb7a2 の再構成がいちばんひどいという順位は再現しなかった。各声 1 発話なので、順位の比較はできない。実録音の comb-HNR は声によって 6.8〜14.0 dB と大きく違うため、比べるときは同じ声の実録音との差で見る。

結論: 声が似ない問題 (7.6) と雑音の問題は、どちらも **decoder が実録音由来の材料を忠実に描き直せない**ことで説明できる。P1 は decoder を主な対象にし、話者の再現と雑音を同じ改修で扱う。v11 の carrier head (調波構造を構造的に保証する decoder の部品) は、comb-HNR 14.6 dB を出して構造としては機能したが、学習の途中で敵対的な学習が崩れて止まった。P1 ではこの結果を出発点にする。N4 には、実録音との差で見る comb-HNR を加える案を、P0 の完了時に登録する。

### 7.9 聞こえる雑音の帯域と、合成フィルタの差し替え (2026-10-29)

雑音の量を段階的に変えた聞き比べ (v10b EMA、同じ clip・同じ seed で `noise_scale` 0 / 0.2 / 0.4 / 0.667、comb-HNR の中央値 15.0 / 11.6 / 8.0 / 6.2 dB) は、聞き手の所見「どちらも雑音が多くて判断できない」で中止した。**乱数なし (comb-HNR 15 dB、実録音並み) でも雑音が多く聞こえる**ので、聞こえる雑音は、乱数で変わる 1〜3kHz の調波の間の雑音ではない。この雑音は一定で、ほかの差を聞き分ける妨げになる (所見「一定の雑音が多いと判断が難しい」)。

帯域を切った試聴 (伏せない、3 声): 合成 (乱数なし) は、**3000 Hz より上を切るとガビガビがほぼ消える**。4000 Hz では消えたか分からない程度で、境目は 3000〜4000 Hz。decoder の帯域分割 (4 帯域、境目 2756 / 5512 / 8269 Hz) では、band0 だけが残る切り方にあたる。

実録音とのエネルギーの差 (全体に占める割合、6 声平均): 合成 (乱数なし) は 1.5〜5.5 kHz が −1.6〜−5.4 dB と少なく、6.5 kHz より上は +2〜+6.5 dB、10〜11 kHz は +11〜+15 dB と多い。再構成は 3〜5.5 kHz で +3.5〜+5.1 dB 多く、10〜11 kHz は +11〜+16 dB 多い。

合成フィルタ (学習で動く PQMF synthesis、`trainable_pqmf_synthesis: True`) を調べた:

| 帯域 | 本来の形からのずれ (差のノルム比) | 帯域の外への漏れ: 今 / 本来 |
|---|---|---|
| band0 | 0.33 | −34 / −77 dB |
| band1 | 0.24 | −31 / −77 dB |
| band2 | 0.40 | −17 / −77 dB |
| band3 | 0.62 | −10 / −77 dB |

実録音を固定の分析フィルタで 4 帯域に分け、合成フィルタでつなぎ直した往復の SNR は、本来のフィルタで 70.0 dB、今のフィルタで 7.6 dB。

同じ重みのまま合成フィルタだけを本来の形に差し替えた (伏せない試聴、6 声):

- 聞き手の所見: 差し替えて良くなる音はなかった。合成 (乱数 0.4 と乱数なし) は差し替えるとガビガビが増え、再構成はほぼ変わらないか今のフィルタの方が良い。
- 数値: 合成 (乱数なし) の 8〜10 kHz は、実録音との差が +4.9 → +13.6 dB に増えた。comb-HNR は 14.3 → 17.6 dB で、ガビガビの増減とは逆に動いた。

decoder が出す帯域ごとの信号 (3 声、今のフィルタで 1 帯域ずつ戻したもの) を実録音と比べると、band2・band3 のエネルギーが実録音より 3〜28 dB 多い (例: 673810f3 の band3 は合成 −17.1 dB、実録音 −44.9 dB)。

読み取り:

- **聞こえるガビガビは、decoder が作る上の 3 帯域 (2.8 kHz より上) の信号に、最後の合成フィルタより前の段階で入っている。** 実録音にはほとんど音がない高い帯域を、decoder が雑音で埋めている。
- 学習で動いたフィルタのずれは、原因ではなく、この雑音を一部抑える方向へ学習した結果とみる。差し替えると抑えていた分が出てくる。ずれた結果、往復の SNR は 7.6 dB まで壊れていて、フィルタとして正しく働いていない。
- comb-HNR は、このガビガビとは逆の向きに動くことがあり、主な音質の指標にはできない。音質の指標の候補は、帯域ごとのエネルギーの実録音との差 (特に 2.8 kHz より上) とする。

帯域ごとの試聴 (decoder の 4 帯域を 1 本ずつ戻した音を、実録音を同じく分けた音と並べる): 聞き手の所見は「**band1 (2.8〜5.5 kHz) からざらざらしている**」。

指標の候補を、ここまでの聴感の判断と照らした:

| 条件 | 2.8 kHz より上のエネルギーの割合、同じ声の実録音との差 | comb-HNR 2.8〜5.5 kHz (実録音 2.39 dB) | 聴感の判断 |
|---|---|---|---|
| 段階 ns 0 / 0.2 / 0.4 / 0.667 | +2.00 / +2.47 / +3.04 / +3.41 dB | 1.97 / 1.17 / 0.72 / 0.62 dB | 隣どうしは聞き分けられない |
| S5′ C0 / C0-self | +0.93 / +1.35 dB | 0.68 / 0.51 dB | 偶然と区別できない (7.7) |
| 合成 ns0 今のフィルタ / 本来のフィルタ | +2.16 / +7.11 dB | 1.81 / 2.12 dB | 本来のフィルタの方がガビガビ |
| 合成 ns0.4 今 / 本来 | +3.33 / +7.93 dB | 0.56 / 0.75 dB | 本来のフィルタの方がガビガビ |
| 再構成 今 / 本来 | +4.25 / +6.71 dB | 0.72 / 1.02 dB | ほぼ同じか、今のフィルタの方が良い |

- 2.8 kHz より上のエネルギーの差は、ここまでの判断とすべて矛盾しない。0.4〜0.6 dB の差は聞き分けられず、2.5〜5 dB の差は聞き分けられた。
- band1 の comb-HNR は、実録音でも 2.4 dB と低い (この帯域の声はもともと調波がはっきりしない)。また本来のフィルタの方を良く出していて、聴感と逆向きなので使わない。
- エネルギーの差だけでは、高い帯域を削っただけのこもった音でも良い値になる。N4 の候補は「2.8 kHz より上の帯域ごとのエネルギーの割合が、同じ声の実録音から上にも下にもずれていないか」とする (500 Hz ごとのずれの平均など)。閾値は、次のモデルの比較で聴感と照らしてから P0 の完了時に登録する。評価専用で、学習の損失には使わない。

P1 の decoder の設計と、候補を比べる手順は [P1 decoder 設計](zero-shot-decoder-p1-design-2026-10-29.md) に分けた。v10b の事後エンコーダーを固定し、decoder だけを学習して、再構成の上の帯域の雑音と話者の保ち方で候補を比べる。

進み具合 (2026-10-30): 数値の判定 (a)〜(c) は D0 と D2-32 が合格し、D2-32 が 3 つの値すべてで上回った。D1 は (b) で不合格 (結果は P1 設計書 §5.7)。開発群の正規化転写率は、v10b の再構成 (own) の CAM++ 0.294 に対して D0 で 0.514、D2-32 で 0.578 となり、上の「own の水準を大きくは超えない」の上限は decoder の差し替えで動くことを確かめた。聞き比べ (d) は D0・D2-32 ともに 10 組中 10 で合格し、P1 を終えた。K1 は D0 (§6 P2 の表)。費用は CloudRift で約 $5.4。

### 7.10 P1 の decoder を v10b の合成に差し替える確認 (2026-10-30、完了)

P1 の decoder は v10b の事後エンコーダーの z を音にするよう学習した。v10b の flow が作る z も同じ空間にあるので、v10b の TTS 経路で decoder だけを P1 の EMA decoder (20,000 ステップ) に替えれば、学習し直さずに zero-shot 合成ができる。P2 の前に、decoder の改善が合成でどれだけ残るかを手元の CPU で確かめた (GPU 費用 $0)。

- 合成: `generate_eval_audio generate --backend torch-ema --decoder-run <P1 の run>` (8bd0e5ef)。条件は P0-3 と同じ (開発群 6 声 + つくよみ、各 72 本、scales 0.4 / 1.0 / 0.5、合成の seed 42・43・44)。実装のハッシュが変わったので manifest は作り直したが、clip・埋め込み・モデル・seed・scales は元の manifest と同じ。
- 評価: `run_zs_eval_set` (CAM++ と ECAPA、cross-utt、v10b の同じ seed を基準にした警告つき)、2.8 kHz より上の帯域ごとのずれ (`measure_highband_deviation`、開発群の実録音と比較)、comb-HNR、CER (whisper-small、CPU、seed 42 のみ、診断用)。
- D0・D2-32 は学習 seed 0 と 1 の 2 本ずつ × 合成の seed 3 つで 6 回、v10b は 3 回。

| 構成 | 開発群 CAM++ | 開発群 ECAPA | つくよみ CAM++ / ECAPA | 2.8 kHz より上のずれ | comb-HNR | CER 中央値 |
|---|---|---|---|---|---|---|
| v10b | 0.246 | 0.237 | 0.194 / 0.118 | 4.61 dB | 6.64 dB | 0.187 |
| v10b + D0 | **0.468** | **0.529** | 0.304 / 0.320 | 3.03 dB | 7.38 dB | 0.194 / 0.202 |
| v10b + D2-32 | **0.509** | **0.555** | 0.428 / 0.325 | 3.20 dB | 8.40 dB | 0.168 / 0.179 |

(開発群とつくよみの値は正規化転写率。CER は学習 seed 0 / 1 の順。)

- 同じ構成の中での広がり (最大 − 最小) は、開発群で CAM++ 0.03、ECAPA 0.04〜0.06。つくよみの ECAPA は D2-32 で 0.27〜0.39 と広い (学習 seed 1 が 0.27〜0.29)。
- 評価器を騙す方向の警告 (goodhart) と ceiling 超えの警告は、どの回にも出なかった。

読み取り:

- **decoder の改善は、zero-shot 合成でもほぼそのまま残る。** 開発群の正規化転写率は、再構成では v10b 0.294 → D0 0.514 だったのに対し、合成でも 0.246 → 0.468 と同じ幅で上がった。held-out の ECAPA は 0.237 → 0.529 と CAM++ 以上に上がった。学習し直していない prior・flow のままでこの差が出るので、v10b で「似ない」原因の大きな部分は decoder にあり、話者の情報は z の段階まではかなり届いている。
- 聞き取りやすさ (CER) は変わらない。
- 2.8 kHz より上のずれは 4.6 → 3.0 dB で、再構成での 4.0 → 1.9 dB ほどは下がらない。合成では、prior・flow が作る z の側にも上の帯域の雑音の元がある可能性がある。P2 (from scratch) で確かめる。
- D2-32 は つくよみの CAM++ と comb-HNR で D0 を上回るが、つくよみの ECAPA が学習 seed で大きく揺れる。P2 の K1 は D0 のまま変えない (P1 の結論どおり)。
- 未確認: 聴感での似方 (P0-4/5 の較正は雑音で中断したまま)。合成の雑音が減ったので、較正の再開を試す候補になる。

### 7.5 P0-8 pt `ã` と記号の欠落 (2026-10-29、確認済み)

学習データを作る経路 (`prepare_multilingual_dataset._phonemize_single`) と、現在の ID 表 (`get_phoneme_id_map("ja-en-zh-es-fr-pt")`、185 記号) で確かめた。

- pt の `ã` (U+00E3) は ID 表になく、黙って落ちている (例: `mão` → `m u`)。ほかの鼻母音 `ẽ ĩ õ ũ` と、`ã` の IPA `ɐ̃` (PUA U+E064) は表にある。
- **ja 以外の 5 言語 (en / zh / es / fr / pt) で、空白・`,`・`.` も落ちている** (es の `¿` も同様)。表にある記号は `?` だけ。モデルは単語の区切りも、読点・句点の位置も見ずに学習している。
- 影響は間の取り方や自然さで、話者の似方 (本計画の主目的) とは別の問題。ただし、直すには ID 表への追加が必要で、既存モデルとの互換が崩れる。P4 は from-scratch で学習し直すため、P4 の学習データを作る前にまとめて直す。直し方 (G2P 側で `ã` を `ɐ̃` にするか ID を足すか、記号の ID の追加、各ランタイムの G2P と ID 表の扱い) は P1 で決める。

- **K1 の 2 本は、日本語 5 話者の平均で、どちらも C の 4 本のどれよりも両 encoder で高い**。K1 は CAM++ 0.405〜0.423、ECAPA 0.386〜0.396。C は CAM++ 0.272〜0.345、ECAPA 0.218〜0.356。2.8 kHz より上のずれも、K1 (2.63〜2.66 dB) が C (2.89〜4.60 dB) のどれよりも小さい。ただし、これは結果を見たあとの読み方なので、合否には使わない。つくよみでは、K1-s1235 の CAM++ (0.264) が C-s1235 (0.315) より低い。
- **同じレシピの C でも、声ごとの flag が立つ**。C-s1237 は C-s1234 との比較で、75e27ad3 に推論 seed 3 つすべてで `goodhart_flag` が立った (CAM++ 0.378 に対して ECAPA −0.049)。§7.12 の C-s1235 (つくよみ) と合わせて 2 本目で、B を登録した理由 (1 本だけと比べると、学習のやり直しの幅だけで印が立つ) を支える。K1 の 6e22f5cd も、C の 4 本で ECAPA が 0.004〜0.207 と低く、測りにくい声である。
- **学習 seed による幅 (C の 4 本、日本語 5 話者の平均)**: 標準偏差は CAM++ 0.036、ECAPA 0.058、2.8 kHz より上のずれ 0.80 dB、comb-HNR 1.5 dB。4 本の最大と最小の差は CAM++ 0.073、ECAPA 0.138 で、推論 seed による振れ (§7.12、各 run の中で CAM++ 0.03 以下、ECAPA 0.04 以下) の約 2.5〜3.5 倍ある。ECAPA の幅は P2 の 0.187 から 0.116 に狭まった。次の比較で、P2′-a と同じ形 (`2 × 標準偏差`) の規則を使うなら、ECAPA では +0.12 程度の効果が要る。それより小さい効果を確かめるには、1 群の本数を増やすか、学習 seed をそろえた対の比較にする必要がある。
- C-s1236・C-s1237 の CER は最大 0.194 で、明瞭度の問題はない。

読み取り (結果を見たあとの読み方で、判定には使わない):

- **似方の差は、z の作り方 (d_z) のほうが継続長 (d_dur) より大きい**。ECAPA では d_z −0.077 に対して d_dur −0.012。CAM++ では d_dur が +0.022 で、本来の推論のほうが (ii) より高い。土台ごとの d_z は C-s1234 が CAM++ −0.027・ECAPA −0.056、C-s1235 が −0.062・−0.098 で、向きはそろう。声ごと (6 名 × 2 土台 = 12) では、d_z が負なのは CAM++ 8・ECAPA 10。
- **posterior の z でも、正規化転写率は 0.5〜0.6 にとどまる**。(i) は合成する発話の実録音そのものから作った z なので、推論の経路 (z の作り方と継続長) で失う量は (i) と (iv) の差 (CAM++ 0.02、ECAPA 0.09) である。似方の失われる量の大きい部分は、z ではなく decoder (と話者の条件付け) の側にある。候補 A が z の分布の違いを完全に埋めても、ECAPA で +0.09 程度が上限の目安になる。
- **高域のずれは、posterior の z のほうが大きい** (3.53 dB に対して 3.24 dB)。高域のずれは z の分布の違いからではなく、decoder の側から来ている。候補 A で高域のずれが減ることは期待しにくい。
- **F0 の標準偏差は、posterior の 47.6 Hz から、推論経路の z では 28.9 Hz に下がる** (継続長による差は −1.2 Hz)。抑揚の平板さ (CLAUDE.md の残課題「韻律の平板さ」) は、継続長ではなく z の作り方 (prior の平均と flow) から来ている。ただし、F0 の情報が prior の側に足りないのなら、decoder を推論経路の z で学習させても戻らない可能性がある。
- comb-HNR は noise を 0 にすると 5.1 → 10.6 dB に上がる (既知の、noise と調波間の雑音の関係と同じ)。z の作り方による差 (+0.8 dB) は小さい。
- CER は (ii) 0.278 が (iv) 0.217 より悪い。MAS の並び (実録音の長さ) に合わせた z のほうが、継続長予測より聞き取りにくい。
- 6 名は C の学習に入っていた話者で、P2 の開発群 (学習外) より値が高い。経路の差の診断であり、学習外の話者での効果の見込みではない。
