## 0. 結論 (先に)

1. **今の zero-shot の改良だけで、予算 (残り約 $742) の中で「本人と分かる」(L1: 48 試行中 36 以上で「本人」) に届く見込みは低い**【推測】。
   - 決め手は decoder。実録音から作った z をそのまま decoder に通しても、正規化転写率は P1 の最良 decoder で 0.51〜0.58 にとどまる (§1.3)。今の最良 K1 (0.414) は、この上限の約 8 割まで来ている。
   - 192 次元 1 本で伝える方式の上限は、過去の調査で 0.5〜0.6 と見積もられている。仮の T = 0.6 は、その上限のちょうど端にある。
   - 大きさ・速さ 1.03 倍の枠では、decoder を大きくする余地がほとんどない。学習 seed による幅 (標準偏差 CAM++ 0.036、ECAPA 0.058) のため、from-scratch の比較 1 回の判定に約 $100〜150 かかる。残りの予算では 4〜5 回しか判定できない。
   - 小さなモデル (2,000 万パラメータ級) が、学習にいない話者で「実録音と同じくらい本人に聞こえる」と人の試験で示した例は、調べた範囲では見つからなかった。
2. **推奨は (b): 短時間の話者適応 (数十秒〜数分の録音で decoder などを学習し直す) を主軸にし、zero-shot はすぐ使える入口として残す**。
   - 文献では、少ない量の音声で適応すると、似方は実録音並みになる。YourTTS (VITS 系) は 20〜61 秒で Sim-MOS が実録音並みになった。VCC 2020 は「同じ人か」を 4 段階で聞く、今回の §3.1 とまったく同じ形式の試験で、約 5 分 (70 文) の学習データから 90% 超が「本人」と判定された。
   - このリポジトリでも、ユーザーは「FT したモデルではがびがびが出ない」と聞いて判断している (v8 計画 §3.15)。
   - 大きさ・速さ・メモリは base とまったく同じで、ランタイムも変えなくてよい (話者ごとに ONNX を 1 つ書き出す)。手元の RTX 4070 Ti SUPER で試せるので、GPU 費用は $0 から始められる。
   - ただし、計画書 §1 の目的 (「未知の話者の参照音声から」) を変えることになる。**ユーザーの判断が先に要る** (§4.1)。
3. **やめるべきこと**:
   - 1 つの変更を from-scratch・2 本ずつで判定する比較を続けること。
   - 条件付けを強める系の変更 (FiLM の上限外し、敵対的な話者の損失、話者 encoder の点数を損失にすること)。
   - 参照の系列を入れる系統を、decoder の上限が残ったまま from-scratch で試すこと (K2、参照融合の続き)。
   - 話者数を増やすことを主な手段にすること。
   - warm restart による回収。

## 2. 「本人と分かる」に必要な水準の見積もり

### 2.1 手元の数値の目盛り【確認】

開発 5 話者の CAM++ の値 (K1-s1234 s42 の評価 JSON、`piper-zs-identity/p2/eval/K1-s1234-s42/secs-run/secs/*.json`):

- ceiling (同じ話者の実録音どうし): 0.731〜0.849、平均約 0.787
- floor (他の開発話者の実録音。声の近さで選んだ話者ではない): 0.471〜0.606、平均約 0.541
- 幅は約 0.25 しかない。正規化転写率 0.414 は、生の SECS では約 0.643。0.6 は約 0.689。

### 2.2 話者照合の考え方からの見積もり【推測】

- 話者照合では、本人どうしの点数 (平均 0.787) と別人どうしの点数 (平均 0.541) の中ほど、約 0.66 (正規化転写率で約 0.5) が、本人と別人を分ける境目に近い。
- **平均で 0.5 に届いても、合成音声の半分ほどは境目より下に落ちる**。声ごとの値は同じ run の中でも大きく散らばる (K1-s1234 で CAM++ 0.29〜0.53、ECAPA 0.07〜0.53)【確認】`p2c_summary.txt`。
- L1 は、6 声 × 8 試行のうち 75% 以上が「本人」であることを求める。そのためには、弱い声も含めてほとんどの試行が境目を越える必要がある。平均ではおそらく **0.7 前後以上** (両 encoder) が要る。
- floor が「声の近い別人」ではなく「ほかの開発話者」なので、聞き手が R− に近い声と比べる場面では、さらに厳しくなる。
- 雑音や音質が判断を支配する問題は別にある。較正の 1 回目 (c1) では、合成は 5 回中 5 回とも「別人」と答えられた (計画書 `:313`)。数値が届いても、音が「合成らしい」だけで別人と判断されうる。
- **人の判断の目盛りはまだない** (P0-4/5 の較正が中断したまま)。上の 0.7 は、話者照合の考え方からの推定にすぎない。仮の T = 0.6 は「本人と分かる」の下限としては甘い可能性がある。

### 2.3 文献: 自動の類似度と人の判断

- **YourTTS** (arXiv:2112.02418) 表 1・表 3【確認: PDF 本文】。SECS は Resemblyzer。
  - zero-shot (学習にいない話者): LibriTTS で SECS 0.754〜0.856、Sim-MOS 3.98〜4.07。GT は 0.931 / 4.22。
  - 英語 2 話者: zero-shot の Sim-MOS は 4.04 / 4.11 で、GT (4.08 / 4.17) とほぼ同じ。録音条件の違うポルトガル語では、zero-shot が 3.35 / 2.77 で、GT (4.31 / 4.65) と大きく離れた。
  - 適応 (20〜61 秒、1,500 step): ポルトガル語の女性話者は Sim-MOS 2.77 → 4.43 (GT 4.65)、男性話者は 3.35 → 4.19 (GT 4.31)。SECS は GT を上回った (0.930 対 0.873)。著者は、モデルが録音条件まで写したためと説明している。**この例では、適応すると、録音条件が学習と違う話者でも似方が実録音並みになった**。
- **VALL-E** (arXiv:2301.02111)【確認: ar5iv 本文】。WavLM-TDNN の SIM で、LibriSpeech は GT 0.754、VALL-E 0.580、YourTTS 0.337。SMOS は 4.5 / 4.38 / 3.45。VCTK では SMOS が GT 4.29、VALL-E 3.81。
  - 生の SIM で GT に 0.17 届かなくても、SMOS は GT に近いことがある。ただし floor が書かれていないので、正規化転写率には直せない。モデルは 6 万時間で学習した大きなもの。
- **VCC 2020** (arXiv:2008.12527)【確認: ar5iv 本文】。
  - 類似度の試験は「同じ人か」の 4 段階 (確実に同じ / たぶん同じ / たぶん違う / 確実に違う) で、「同じ」の 2 つを足して率にする。**計画書 §3.1 と同じ形式**。
  - 1 話者あたりの学習データは 70 文 (約 5 分)。言語内の課題では、上位 8 システムで 90% を超える音声が「本人」と判定され、実録音と有意な差がなかった。
  - これは話者ごとに学習する声質変換で、zero-shot ではない。論文は、人は自動の話者照合よりずっと聞き分けが下手だとも述べている。
- **小さな zero-shot モデル**:
  - arXiv:2501.08566 (2,250 万パラメータ)【確認: HTML 本文】: SIM 0.73、MOS_sim 3.31。CosyVoice (4 億パラメータ) は 0.84 / 3.73。GT の値は書かれていない。
  - SupertonicTTS (4,400 万パラメータ): SIM 0.472、実録音 0.677【未確認: 付録 1 の引用】。
  - **2,000 万パラメータ級で、学習にいない話者について人の類似度が実録音並みだと示した例は見つからなかった**。
- **自動の類似度と人の評価の相関**:
  - x-vector の cosine と聴取試験の相関 r = 0.89 (arXiv:2011.04839)。
  - 発話ごとに人の類似度を予測するモデルで 0.78 (arXiv:2207.00344)。
  - どちらも【未確認: 検索結果の要約のみ】。相関はあるが、「どの値から本人に聞こえるか」の閾値を示した文献は見つからなかった。
- ZeSTA (arXiv:2603.04219) の「最新の zero-shot でも FT に 0.04〜0.07 届かない」(研究文書 `similarity-research.md:96`)【未確認: 要旨にこの数値はなかった】。

**見積もりのまとめ**【推測】:

- 「本人と分かる」には、両 encoder で正規化転写率 0.7 前後以上と、合成らしさが判断を支配しない音質の両方が要りそうだ。
- 今の構造での上限 (再構成で 0.51〜0.58、1 本のベクトルで 0.5〜0.6) は、それより下にある。
- 文献で人の判断が実録音並みになったのは、大きなモデル (VALL-E、CosyVoice 級) か、**話者ごとの適応** (YourTTS の適応、VCC) だけだった。

### 3.1 (b) を勧める理由の詳細

1. **最大の律速を正面から外せる**。zero-shot では、decoder が一度も聞いたことのない声を描く必要がある。適応では、その声の実録音で decoder (と必要なら enc_p・flow) を学習し直す。§7.6 で見つかった「再構成でさえ声が保たれない」問題が、そもそも起きにくくなる【推測】。
2. **手元の証拠**:
   - ユーザーは「zero-shot はがびがび + 参照に似ていない。FT したモデルでは出ない」と聞いて判断している【確認】v8 計画 `:1067`、`:1094` (「FT でがびがびが消えるのは decoder が単一話者に合わせて学習し直されるため」)。
   - ただし、FT したモデルが「本人に聞こえる」かを伏せた試験で確かめた記録はない。公開記録では、CAM++ での比較に結論が出ていない (FT 0.662 対 zero-shot 0.696、参照が FT のコーパスに含まれる条件)【確認】`tsukuyomi-zs-v1-release-2026-10-10.md:83-96`。
3. **文献の証拠**: YourTTS の適応 (20〜61 秒、1,500 step で Sim-MOS が実録音並み)、VCC 2020 (約 5 分で 90% 超が「本人」、試験形式は §3.1 と同じ)、residual adapter (arXiv:2210.15868、話者ごとに base の約 0.1% のパラメータで、全体の FT と同等の似方)【確認: 要旨】。
4. **制約との相性**:
   - 同じ構造の重みなので、N5 (大きさ・速さ・メモリ 1.03 倍) は自動的に満たす。
   - CAM++ 以外の encoder も足さない。
   - 学習データは base が商用利用可のデータだけで、適応に使う録音はユーザーが用意する本人の録音。
5. **費用と速さ**:
   - 1 声あたりの適応は、手元の RTX 4070 Ti SUPER で済む見込みが高い。
   - decoder だけの学習の道具 `src/python/piper_train/tools/train_decoder_only.py` (P1 で使用) と、FT の手順 (CLAUDE.md の Template B) がすでにある。
   - 学習 seed による幅の影響は、話者ごとの効果が大きい (YourTTS では Sim-MOS で +0.8〜+1.7) ので小さい【推測】。
6. **zero-shot の成果は無駄にならない**。K1 の decoder の改善は、適応の出発点としても効く。適応前の zero-shot は「すぐ使える近い声」として残せる。

### 3.2 (b) の危険と注意

- **目的の変更**: 計画書 §1 は「未知の話者の参照音声から合成した声」を目的にしている。適応は、録音を数十秒〜数分と、学習の時間 (GPU で数分〜1 時間) を必要とする。ユーザーがこれを目的の内側と見るかどうかが最初の分かれ目。
- **評価の扱い**:
  - §3 の最終判定は zero-shot を前提にしている。適応を加えるなら、最終群の話者ごとに「適応用の録音 (試験の文・参照と重ならないもの)」を事前に決め、新しい規則として**別名で登録**する (計画書 `:88` の決まり)。
  - 最終群の音声は、登録まで取得しない。
- **数値の読み方**: 適応すると、録音条件まで写して SECS が ceiling を超えることがある (YourTTS 表 3)。`above_ceiling_flag` が立つのは、ここでは異常というより予想どおりと考え、聴感を主にする。
- **少ないデータで崩れる**: YourTTS では 45 秒未満で自然さ (MOS) が下がった。過学習と、日本語以外の言語の劣化 (YourTTS は元のデータを混ぜて防いだ) に注意する。聞き手 1 名が日本語で使うなら、他言語の劣化は許せる可能性がある (要確認)。
- **配布の形**: 話者ごとに 40 MB の ONNX になる。差分 (LoRA など) だけを配る形はランタイムの変更が要るので、最初は「書き出し時に重みを合成して普通の ONNX にする」形にする。

## 4. 推奨の進め方

### 4.1 ユーザーに先に決めてもらうこと

1. **適応を目的の内側と認めるか**: 「数十秒〜数分の本人の録音と、数分〜1 時間の適応で本人と分かる」でよいか。認めないなら、(a) を安い候補に絞って続け、達成できない見込みも含めて計画書に書く。
2. **人の判断の目盛りを先に取るか**: P0-4/5 の較正は雑音で止まっている。K1 は 2.8 kHz より上のずれが 2.64 dB と、v10b (4.61) より小さい。開発 5 話者 (つくよみは除く) で R+ / R− / Z+(K1) の短い試験をすれば、今の 0.41 が耳でどこにいるかが分かる。GPU 費用はかからない。
   - 注: 計画書 §3 は、つくよみを「聴感試験の最終群にだけ入れる」と書く一方、§7.4 の較正では開発群 6 声 (つくよみを含む) を使っている。どちらに従うかの確認が要る。

### 4.2 (b) を認める場合の小さな確認 (GPU 費用 $0、手元)

1. 土台: K1-s1234 (または C) の ep40 EMA。
2. 対象: 開発 5 話者。適応用の録音を 30 秒・1 分・3 分の 3 段に分け、評価の参照・cross 用の実発話・試験の文と重ならないものにする。
3. 比べるもの: (i) 全体の FT (Template B の学習率)、(ii) decoder だけの FT、(iii) decoder + enc_p の条件付け部分の FT。学習の長さは事前に固定する。
4. 測るもの: 正規化転写率 (両 encoder、適応に使っていない発話との cross-utt)、CER、2.8 kHz より上のずれ。そのうえで、ユーザーの聞き分け (R+ / R− / Z+ / 適応 Z+)。
5. 事前登録 (例): 開発 5 話者で、1〜3 分の適応の H(Z+) が 0.75 以上、かつ R− より明らかに高い。

### 4.3 (a) で続ける価値のあるもの

- 付録 1 の A (合成経路の z でも decoder を学習する) は、decoder だけの学習で安く試せる。zero-shot と適応の両方の土台を良くするので、続ける価値がある。
- B (flow の重み共有 + 大きな decoder) は from-scratch が要るので、(b) の結果を見てからにする。

### 4.4 やめるべきこと (理由つき)

| やめること | 理由 |
|---|---|
| 1 つの変更を from-scratch・2 本ずつで判定する比較 | 学習 seed による幅のため、+0.12 未満の効果は見分けられない。1 回 $100〜150 で、残りの予算では 4〜5 回しかできない。続けるなら、学習 seed をそろえた対の比較か、decoder だけの学習で先に振り落とす |
| 条件付けを強める系 (FiLM の上限外し、敵対的な話者の損失、encoder の点数を損失にすること) | F は下がった。v10a と v11 は encoder を騙す方向に崩れた。decoder が g を使わない状態では空振りする |
| 参照の系列を入れる系統 (K2、参照融合の続き) を from-scratch で試すこと | 3 試行すべて不合格。速さの枠を超え、ランタイムの変更が最も大きい。decoder の再構成の上限が残る限り、利得を描き出せない公算が大きい |
| 話者数を増やすことを主な手段にすること | 571 → 3,692 で改善しなかった。データ拡充をするなら、録音条件の幅を広げる目的に限る |
| warm restart による回収 | v9 の 7 介入で回収できないことが確定している |
| 仮の T = 0.6 を「本人と分かる」の十分条件として扱うこと | §2.2 のとおり、話者照合の考え方からは 0.7 前後が要りそうで、人の判断の目盛りもまだない |
