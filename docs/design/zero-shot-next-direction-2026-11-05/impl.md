## 0. 要約

1. **推論経路の z は、学習用のデータに音素列を足せば、MAS の並びで実録音と 1 フレーム単位でそろえて作れる。** decoder だけの学習のデータ (P1 の 4,776 発話) には音素列がないが、手元の jsonl (299,728 行) と発話 ID で 4,776/4,776 つながることを確かめた【確認】。韻律の値 (a1〜a3) は継続長予測だけが使うので、MAS で並べる A では要らない【確認】。
2. z の作り方は 3 通りを並べる。
   - **A1 (推論と同じ乱数)**: `z = flow⁻¹(m_p[MAS] + 0.4·exp(logs_p[MAS])·ε)`、ε は独立。推論の z と同じ分布だが、音の高さの細かい動きは実録音と合わない。
   - **A2 (実録音の残差を縮める)**: `z = flow⁻¹(m_p + λ·(flow(z_q) − m_p))`。実録音と細部まで相関するが、decoder が「縮めた細部を元の大きさに戻す」ことを覚え、推論では乱数の細部を大きくしてしまうおそれがある (§5.3)。
   - **A-ctl (対照)**: 今の道具のまま posterior の z だけ。同じステップ数・同じ判別器で、A の差を「decoder をもう一度学習した効果」から分ける。
3. 損失は、バッチを半分ずつに分ける (posterior 8 本 + 推論経路 8 本)。推論経路の半分では、**mel L1 をそのまま当てると、音の高さのずれを埋めるために調波の間に音を足す方向へ押す**おそれがある (§5.2)。そこで、推論経路の半分には判別器の損失と「スペクトルの包絡 (声の響きの形) の損失」だけを当てる A1e を A1 と並べる。
4. 変更は `tools/train_decoder_only.py` が中心 (データ準備・`step()`・候補表・CLI)。z を作る処理は、推論 (`models.py` `infer`) と同じコードを通すために `models.py` に小さな共通の関数を 2 つ切り出すのを勧める (過去に推論の手書き複製で配線が切れた事故 `ca76d6ea` がある)。
5. 安い事前診断を先に置く (§6、$0)。C の decoder のまま、同じ発話を「posterior の z」「MAS の並びの推論経路の z」「本来の推論 (継続長予測)」で音にして比べる。ずれの原因が z の分布か継続長かを分けられ、A が効く余地があるかを学習前に判断できる。
6. 組み合わせ: 位相の損失・調波/CQT 判別器・帯域分割 MRD は学習のときだけの変更で、同じ道具で試せる。D (posterior の入力の声を揺らす) も同じ道具で試せるが、音の高さを保って声の響きだけ変える前処理が要る。E (g からの低ランク混合) と Snake (α を学習する形) は、**数 KB でもパラメータが増えるので、大きさの規則「v10b 以下」を厳密に読むと単独では不合格**になる (§8)。
7. 費用: P1 の実績 (RTX 4090 で 2.8 it/s、2 万ステップ約 2 時間、VM $0.78/時で GPU 2 枚) から、A-ctl は 1 本約 $0.8、A1・A2 は z を作る分で 1.3〜1.6 倍とみて 1 本約 $1.0〜1.3。調査付録の「1 本 $3〜6」は高すぎる。8 本の比較で VM の立ち上げ込み約 $12〜20。手元の RTX 4070 Ti SUPER なら $0 で 1 本 4.5〜8 時間。評価は手元 CPU で 1 本 (推論 seed 3 つ) 約 75 分。

## 2. 推論経路の z の作り方

### 2.1 データ: 音素列を足す

- `prepare()` (`train_decoder_only.py:505-585`) に引数 `--dataset-jsonl` を足し、`audio_path` の basename の stem (例 `18460462_0020`) で発話をつなぐ。`index.json` の各発話に `phoneme_ids` と `language_id` を足し、schema を `decoder-only-data/2` などに上げる。つながらない発話があれば止める (黙って捨てない)。
- 既存の P1 データ (`p1/data`) は作り直さず、`index.json` に音素列を書き足す小さな補助コマンド (`attach-phonemes`) でもよい。音声 (`audio/*.npy`) と埋め込みは変わらない。
- 韻律の値 (`prosody_features`) は MAS で並べる限り要らない。継続長予測を通す変種 (§2.6) を作るときだけ要る。
- `SegmentDataset.__getitem__` (`:460-468`) が `phoneme_ids` を返し、`collate` (`:471-481`) で 0 埋めして `phoneme_ids [B, T_x]` と `phoneme_lengths [B]` を作る。`language_ids` は今は 0 固定 (`:480`) で、ja だけなら変えなくてよい。

### 2.2 z の作り方 (1 ステップの中で、勾配なし・fp32)

今の `step()` の `with torch.no_grad():` (`:239-256`) の中に足す。flow は fp32 のまま通す (今の no_grad 部分は autocast の外にあるので既にそうなっている【確認】)。bf16 だと `flow⁻¹(flow(z))` の誤差が増えるおそれがある【推測】。

```text
g, g_spk, g_lang = model_g._get_global_conditioning(None, lid, speaker_embeddings=emb, return_components=True)   # models.py:1586-1649
x, m_p, logs_p, x_mask = model_g.enc_p(phoneme_ids, phoneme_lengths, g=g, g_spk=g_spk)                         # models.py:1870
logs_p = logs_p.clamp(-8, 8)                                                                                    # models.py:1882
z_q, m_q, logs_q, y_mask = model_g.enc_q(spec, frames, g=g)                                                     # 今の道具と同じ (:242)
z_p_q, _ = model_g.flow(z_q, y_mask, g=g_lang, g_spk=g_spk)                                                     # models.py:1889 (SNAC)
attn = MAS(z_p_q, m_p, logs_p, x_mask, y_mask)                                                                  # models.py:1894-1916 と同じ計算
m_pf  = attn @ m_p ; logs_pf = attn @ logs_p ; 再 clamp                                                          # models.py:1936-1937, 1956-1957
A1:  z_A = flow⁻¹(m_pf + ns · exp(logs_pf) · ε, y_mask, g=g_lang, g_spk=g_spk)                                  # models.py:2198-2201 と同じ
A2:  z_A = flow⁻¹(m_pf + λ · (z_p_q − m_pf), ...)
z_A = z_A * y_mask
```

- 区間の切り出しは今の `ids` (`:243-247`) をそのまま使う。z_A は z_q と同じフレーム数なので、`slice_segments(z_A, ids, 64)` と `y = audio[ids·hop : (ids+64)·hop]` が同じ時間を指す【確認: attn は `[b,1,T_y,T_x]` で T_y = y のフレーム数】。
- **共通の関数に切り出す (推奨)**: MAS の計算 (`models.py:1894-1916`) を `SynthesizerTrn._mas_attention(z_p, m_p, logs_p, x_mask, y_mask)` に、引き伸ばし・clamp・乱数・flow の逆変換 (`models.py:2172-2203` のうち f0 以外) を `SynthesizerTrn._prior_latent(attn, m_p, logs_p, y_mask, g, g_spk, g_lang, noise_scale, eps=None)` に切り出し、`forward` と `infer` の両方からも呼ぶ。道具はこの 2 つと新しい公開メソッド `prior_path_latent(x, x_lengths, spec, spec_lengths, lid, speaker_embeddings, noise_scale, residual_scale=None)` を呼ぶだけにする。理由: 推論の手順を道具の中に書き写すと、SNAC の引数・F0 の残差・clamp の順番がずれたときに、学習した z と推論の z が黙って食い違う。export の手書き複製で AdaLN の g_spk が切れた事故 (`ca76d6ea`) と同じ型【確認: コミットの内容】。切り出し前後で `forward`・`infer` の出力が一致するテスト (乱数を固定) を先に書く。
- `use_f0_path` (C は false) の場合は `_apply_f0_prior_residual` を同じ順番で通す (`models.py:1939-1945`, `2179-2185`)。C では通らないが、共通の関数にしておけば将来のモデルでも食い違わない。

### 2.3 時間の対応

- MAS の並びは、その発話の実録音の posterior から求めるので、音素の境目の位置は実録音と同じ【確認: `models.py:1911-1916`】。継続長の予測の誤りは A の学習には入らない (推論との違いとして残る)。
- 音素の中の細かい動き (音の高さの上下、強さ、声の立ち上がり) は、A1 では乱数 ε から flow⁻¹ が作るもので、実録音とは合わない。prior の平均 m_p は音素の中で一定で、flow の畳み込みが前後をなめらかにつなぐだけ【確認: `models.py:1936`、flow の WN は時間方向の畳み込み】。これが §5.2 の問題の元。
- A2 では残差 `z_p_q − m_pf` が実録音の細部を持つので、λ に比例して細部が合う。

### 2.4 noise_scale (ns) と λ

- A1 は ns = 0.4 に固定する (評価条件と配布の既定)。0.667 で使う利用者もいるので、評価だけ 0.667 も参考に測る。ns を範囲から引く案 (例 0〜0.667 の一様) は、比べる条件が増えるので最初の比較では使わない。
- A2 の λ は「残差を prior の幅で割った値」の標準偏差 `σ_r = std((z_p_q − m_pf)/exp(logs_pf))` を事前診断 (§6) で測ってから決める。prior が実録音によく合っていれば σ_r ≈ 1 で、λ = 0.4 が推論の分布と同じ幅になる【推測】。KL の値 (C で 1 フレームあたり約 2.6、192 次元の和) だけでは σ_r は決まらない (logs_p − logs_q の項が混ざる、`losses.py:68-73`)。

### 2.5 計算量

- 追加は enc_p (音素 約 120 個、6 層) と flow の順・逆 2 回 (発話全体、約 430 フレーム、各 4 段)。どれも勾配なし。flow は decoder の 1 フレームあたりの計算より重く、発話全体を通すので、1 ステップは 1.3〜1.6 倍になるとみる【推測、要実測】。MAS は Super-MAS があれば GPU、なければ Cython (CPU) で、バッチ 16 なら数 ms【推測】。
- 速さが足りなければ、(a) MAS の並びを `m_q` (乱数なし) で発話ごとに 1 回だけ求めて保存し、(b) flow を切り出し区間の前後 32 フレームずつ (flow の受容野、WN カーネル 5・4 層 × 4 段) を足した 128 フレームだけに通す。(b) は端の数フレームを除けば発話全体で通したのと同じ値になる【推測: 受容野の計算から。テストで確かめる】。

### 2.6 継続長予測を通す変種 (採らない)

本当の推論と同じく継続長予測で並べると、z のフレーム数が実録音と違い、mel・STFT・特徴の一致の損失が使えない。判別器だけで学習することになり、不安定さが大きい。最初の比較には入れない。

## 3. 当てる損失

### 3.1 バッチの分け方

- バッチ 16 を前半 8 本 (posterior の z) と後半 8 本 (推論経路の z) に分ける。サンプルごとに乱数で混ぜるより、損失の計算が今の関数のまま使える (`sub_stft_loss`・`full_stft_loss` はバッチ平均のスカラーを返す)。割合は事前に 1:1 と決めておく (調査付録 A の「半々」と同じ)。
- 判別器 (`model_d`、`model_d_mrd`、帯域分割 MRD) には 16 本全部を偽物として渡す。判別器は z を見ず波形だけを見るので、推論経路の音にも同じ意味で効く。JCU MRD の話者の条件は CAM++ 埋め込みで (`train_decoder_only.py:266`)、学習とともに変わる判別器なので、固定 encoder の点数を目標にしない決まり (契約 §2-4) に反しない【確認: v10a の失敗は固定 CAM++ の cosine を目標にしたことが原因、`zero-shot-v10-design.md` §10】。

### 3.2 腕ごとの損失

| 腕 | posterior の半分 | 推論経路の半分 |
|---|---|---|
| A-ctl | 今のまま (mel 45、sub-band STFT 1、全帯域 STFT 0.5、MPD/MSD、MRD、帯域分割 MRD、特徴の一致) | (半分に分けず 16 本とも posterior) |
| A1 | 今のまま | 今のまま (HiFi-GAN の GTA 調整・SC-GlowTTS と同じ形。実録音と細部が合わなくても対の損失を当てる) |
| A1e | 今のまま | 判別器の損失 (敵対) + スペクトルの包絡の損失のみ。mel L1・STFT 損失・特徴の一致は当てない |
| A2 | 今のまま | 今のまま (λ = 0.4/σ_r) |

スペクトルの包絡の損失 (A1e): 正解と生成の log-mel (80 bin、今の `mel_spectrogram_torch`) を離散コサイン変換し、低い方の 20 次 (フレームごと) だけで L1 を取る。音の高さの細かい調波の位置はほぼ消え、声の響きの形 (話者らしさの主な部分) と強さの時間変化が残る【推測: MFCC と同じ考え方。20 次で調波がどれだけ残るかは単体テストで、同じ声で F0 を 10% ずらした実録音の組の損失が小さいことを確かめる】。実録音を正解にした損失で、評価の指標 (帯域のずれ、SECS、comb) ではないので、契約の禁止の対象外。係数は mel と同じ桁になるよう、学習前に実録音どうしで大きさを測って決める。

### 3.3 位相の損失を足す場合

位相の損失 (音質の調査の候補 1) は posterior の半分だけに当てる。推論経路の半分の波形は実録音と位相がそろう理由がない。

## 5. 失敗しうる点

### 5.1 推論経路の z と実波形の位置ずれ

- 音素の境目は MAS でそろう【確認】。ずれが出るのは音素の中の細部だけ (§2.3)。
- 推論では継続長が予測なので、A で学習した decoder でも、継続長の誤りによる不自然さは直らない【推測】。§6 の診断で「MAS の並びの推論経路」と「本当の推論」の差を見れば、継続長の分の大きさが分かる。

### 5.2 分布が違う z で mel 損失と判別器がどう振る舞うか

- **mel L1 が調波の間を埋める方へ押すおそれ (A1)【推測】**: 推論経路の z では音の高さの動きが実録音と合わない。80 bin の mel は 1〜3 kHz で 1 bin あたり 100〜200 Hz ほどで、声の倍音 (100〜300 Hz 間隔) の山と谷がある程度見える。正解の山の位置が分からないまま L1 を下げる一番の答えは、山と谷の中間 (調波の間にも音がある状態) で、これは今の雑音 (調波の間の雑音、comb-HNR の低下) と同じ向き。GTA 調整 (HiFi-GAN、SC-GlowTTS) で問題になりにくいのは、入力の mel が正解の音の高さをかなり保っているためで、VITS の prior の z は音素の中で平坦なので条件が悪い【推測】。対処が A1e (推論経路の半分は包絡の損失と判別器だけ)。
- **特徴の一致の損失 (feature matching)** も対の損失なので同じ向きに働く【推測】。A1e では外す。
- **判別器は対ではない**ので、推論経路の音にもそのまま「本物らしさ」を求める。今の雑音の帯域 (2.8 kHz より上) は帯域分割 MRD が見る【確認: P1 D0】。ただし判別器が推論経路の音だけを見分けやすくなると、敵対の圧力が増え、v11 のように崩れる余地が増える (v11 は話者の敵対学習の段階的な強化で崩れた、`zero-shot-v11-roadmap.md` §5)【推測】。判別器の損失と生成側の敵対損失の推移を posterior・推論経路の半分ごとにログに出し、推論経路の側だけ判別器が勝ち切る (偽物の点が 0 に張り付く) ときは止める。
- **8 月の「経路盲目」の診断との関係【確認】**: v10b 残存ノイズ診断は、当初「decoder は posterior の z しか見ていないので推論の乱数の雑音に学習の圧力がない」と考えた (§6 H-C)。しかし実測で、学習中に損失が見ていた再構成そのものも comb-HNR 6.71 dB と汚く (§8)、雑音の主な原因は「z の細かい中身を調波にそろえずに波形にすること」と直された。したがって **A で comb-HNR 型の雑音 (1〜3 kHz の調波の間) が直るとは期待しにくい**。A がねらうのは、計画書 §7.10 で残った「再構成 1.9 dB に対し合成 3.0 dB」という 2.8 kHz より上のずれの差と、話者の似方。
- 調査付録の「過去に推論経路の z で decoder を学習した記録はない」は、学習した記録としては正しい【確認: `git log --all` を検索】。ただし考え方は上の「経路盲目」(2026-08-20、`a917bdfa` ほか) と、v10 設計の「完全 prior 経路 cycle (text→enc_p→flow⁻¹) は不採用: コスト 3 倍級 + 初期不安定」(`zero-shot-v10-design.md:81`、from-scratch での検討) で一度出ている。

### 5.3 A2 (残差を縮める) の特有の問題

- A2 では decoder が `f(m_p + λ·r) ≈ y` を覚える (r は実録音の本当の残差)。λ < 1 で学習すると、decoder は「縮んだ細部を元の大きさに戻す」写像を覚える。推論では r の代わりに乱数 `ns·exp(logs_p)·ε` が入るので、decoder は乱数の細部を約 1/λ 倍に広げて描く。つまり、低い温度 (ns 0.4) で引いたなめらかな z を、ns 1 で引いたときのような細部の多い音にしてしまうおそれがある【推測】。
- ns を上げると雑音が増えることは測られている (v10b で ns 0 / 0.2 / 0.4 / 0.667 → 2.8 kHz より上のずれ +2.00 / +2.47 / +3.04 / +3.41 dB、計画書 §7.9)【確認】。A2 はこの方向に動く危険がある。一方、抑揚の幅 (F0 の標準偏差が実録音の約 6 割、v10b 品質計画 §9) は広がる方向で、良い面もありうる【推測】。
- A2 は比べる価値はあるが、主な候補は A1・A1e とする。

### 5.4 学習の話者が 48 名しかないこと

- P1 の学習データは 48 話者・6.9 時間 (P1 設計書 §5.5)【確認】。posterior の z では声の情報が z から来るので、話者が少なくても学習外の話者に効いた (P1 の結果)。推論経路の z では、声の情報は g (CAM++ 埋め込み → spk_proj) から enc_p と flow を通って来るだけなので、decoder が「この 48 名の g ならこの声」と覚えると、学習外の話者では効かないか、学習した声のどれかに寄るおそれがある【推測】。寄った場合は、評価の Z− (別話者の参照から作った合成) も本人に似て見える形で出る。
- 対処: 推論経路の半分に使う話者を増やす。jsonl にある moe-speech-plus の 457 名 (開発群・最終群の 10 名は jsonl に 0 行)【確認】から、同じ 6.9 時間のまま話者を 200〜450 名にする (1 名あたり 10〜25 発話)。話者ごとの zip を HF から取り直す必要がある (P1 と同じ手順、`prepare` の除外の検査 `:515-517` はそのまま効く)。最初の比較で 48 名のまま回すなら、そのことを判定の注意として書いておく。

## 6. 事前診断 ($0、手元)

A を学習する前に、A が効く余地があるかを C の decoder のまま測る。

- 材料: jsonl に音素列がある moe-speech-plus の話者のうち、P1 の 48 名以外から 6 名 × 10 発話 (C の学習には入っていた話者なので、学習外の話者の評価ではなく、経路の差を見る診断)。開発群の発話は音素列がつながらないので使わない (書き起こしを G2P に通せば使えるが、学習時と同じ版の G2P である保証が要る)。
- 同じ発話を C ep40 EMA (C-s1234 と C-s1235) で次の 4 通りに音にする: (i) posterior の z (今の再構成)、(ii) MAS の並び + 推論経路 ns 0.4、(iii) MAS の並び + ns 0、(iv) 継続長予測の本当の推論 ns 0.4。(ii)(iii) は §4 の `recon --z-source` で作れる。(iv) は同じ文の通常の合成。
- 測るもの: 2.8 kHz より上のずれ (`measure_highband_deviation`、同じ話者の別の実録音と比べる)、CAM++・ECAPA で同じ話者の別の実発話との類似度、comb-HNR。あわせて σ_r (§2.4) を全フレームで出す。
- 読み方:
  - (i) と (ii) の差が大きい → z の分布の違いが原因で、A が直接ねらえる。
  - (ii) と (iv) の差が大きく、(i) と (ii) の差が小さい → 原因は継続長で、A は効きにくい。
  - (ii) と (iii) の差 → ns による分。
- 費用: 手元の CPU で 2 土台 × 4 通り × 60 発話。合成と評価で数時間【推測】。
- v10b ep79 と、P1 の D0 decoder を v10b に差したもの (§7.10 の構成) でも同じ 4 通りを測ると、§7.10 の「再構成 1.9 dB に対し合成 3.0 dB」の差が z と継続長のどちらから来るかも分かる。

## 7. 比較の組み方と判定の案 (事前登録は呼び出し側で決める)

- 土台: C-s1234 と C-s1235 の ep40 EMA (C の 4 本の弱い方と強い方)。土台を 2 本にするのは、効果が土台によらず出るかを見るため。P1 では decoder だけの学習の学習 seed による差は小さかった (D0 の s0/s1: CAM++ 0.509/0.518、ECAPA 0.450/0.467、P1 設計書 §5.7)【確認】ので、ふるいは各土台 1 seed で回し、残った腕だけ 2 seed 目を足す。
- 腕: A-ctl、A1、A1e、A2 の 4 つ × 土台 2 = 8 本。全腕で帯域分割 MRD あり、合成フィルタ固定、20,000 ステップ、バッチ 16、他は P1 と同じ (`train_decoder_only.py:142-157`)。
- 評価: 合成 (TTS の経路) を主にする。`generate_eval_audio generate --backend torch-ema --decoder-run <run>` (§1)、開発群、推論 seed 42/43/44 × 参照 2 本、`run_zs_eval_set --encoder2`、`--baseline` は同じ土台・同じ seed の A-ctl。再構成 (`recon`) も測り、posterior の経路を悪くしていないことを確かめる。
- 判定の案:
  - 両土台で、A の腕の日本語 5 話者の平均の正規化転写率が、同じ土台の A-ctl を CAM++・ECAPA とも +0.05 以上上回る (§7.10 で decoder だけの学習の同じ構成の中の広がりが CAM++ 0.03、ECAPA 0.04〜0.06 だったことから。2 seed 目を足した後に、2 seed の差の 2 倍と比べて確かめ直す)。
  - 合成の 2.8 kHz より上のずれが A-ctl より小さく、「合成 − 再構成」の差が縮む。
  - CER median ≤ 0.30、`above_ceiling_flag` なし、声ごとの `goodhart_flag` は A-ctl 比で両土台に共通して立つ声がない。
  - Z− 側 (別話者の参照からの合成と本人の似方) が A-ctl より上がっていない (§5.4 の「学習した声に寄る」の確認)。
- 途中で止める条件: 推論経路の半分で判別器の偽物の点が 0 に張り付く、mel/包絡の損失が発散、5,000 ステップの合成で CER median が 0.6 を超える。

| GAN の損失の形 (SAN、相対比較 + R1/R2) | 試せるが手間が大きめ | `losses.py` の判別器・生成側の損失に別の形、各判別器の最後の層を切り替え。C から読み込んだ判別器は最小二乗で学習済みなので、最後の層を初期化し直す必要がある | 学習のときだけ。R1/R2 は判別器の学習が 1.3〜2 倍遅い【推測、調査付録】 | 変える部品が多く、A の効果と混ざる。A の結果の後に回す |
| D (posterior の入力の声を揺らす) | 試せる | 音の高さを保って声の響き (フォルマント) だけをずらした音声を前処理で作る (pyworld などで包絡を周波数方向に伸縮して再合成。ライセンスは採用前に確認)。データの写しが 1 組増える (約 2.2 GB)。`SegmentDataset` が元と揺らした音声の両方を返し、`step()` は揺らした方から spec を作って enc_q に、正解 y と g は元のまま。約 80〜120 行 + テスト。GPU の上で線形スペクトログラムを周波数方向に伸縮する安い方法は、倍音の間隔 (音の高さ) まで変わり、decoder が z の音の高さを無視することを覚えるおそれがあるので勧めない【推測】 | 推論は変わらない | A の推論経路の半分では、声の情報はもともと g からしか来ない。A と D は同じねらい (decoder に g から声を描かせる) で、A が効けば D の上積みは小さいかもしれない【推測】。D は posterior の半分に入れる |
| E (g からの低ランクのチャネル混合) | decoder の形が変わるので、P1 の D2/D4 と同じく候補表に足せば試せる | `mb_istft.py` の s1 段 (`:1055-1080` の upsample 段の後) に `x + U·diag(s(g))·Vᵀx` (ゼロから始める) を足す opt-in のフラグ、`measure_variant_cost.py` の `VARIANTS` (`:279-325`) に変種、道具の `CANDIDATES` に候補、ONNX の一致テスト。約 120〜180 行 | **r 16・128 チャネルでも U・V と s(g) で約 1.2 万パラメータ (FP16 で約 25 KB) 増え、「v10b ep79 の正式版 40,763,422 バイト以下」を超える**。D0/C は正式版とバイト数が同じで余裕が 0【確認: 計画書 §7.12 P2-f の表】。flow の縮小 (P2-g の Cf の確認が前提) と組むか、規則の扱いをユーザーが決める必要がある | 調査付録の指摘どおり、decoder が g を使わない状態では空振りしうる。A か D の後に試すのが筋 |
| Snake 活性化 | 試せる (decoder の形が変わる) | `mb_istft.py:1056`・`:1082` と resblock の中の `leaky_relu` を切り替えるフラグ。約 40〜60 行 | **α をチャネルごとに学習すると数千パラメータ増え、大きさの規則を厳密には超える**。α を 1 に固定した形ならパラメータは増えない。速さは C の p50 が正式版の 1.016 倍 (P2-f) で余りが 1.4 ポイントしかなく、Sin の分で超えるおそれ。学習の前に `measure_variant_cost` で測る ($0) | A とは独立。速さで落ちる見込みが高い【推測】 |

まとめ: A と同じ道具で、追加の大きさ・速さなしに試せるのは、帯域分割 MRD (既に入っている)、位相の損失、調波/CQT 判別器、GAN の損失の形、D の 5 つ。E と学習する Snake は大きさの規則に触れる。
