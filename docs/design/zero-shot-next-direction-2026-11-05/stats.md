## 0. 要点

1. 【確認】C の 4 本の揺れは、ほぼすべてが学習 seed によるもの。日本語 5 話者の平均で、学習 seed の SD は推論 seed の SD の 4.0 倍 (CAM++)・5.7 倍 (ECAPA)。2.8 kHz より上のずれは 18 倍。
2. 【確認】同じ run の中で CAM++ と ECAPA の動きはほとんど連動しない (C の中の run 間の相関 +0.13、声ごとのずれの相関 +0.06〜0.09)。そのため「ある声で CAM++ だけ上がる」形は偶然でよく出る。**同じレシピの C どうしを 1 本対 1 本で比べると、12 組中 7 組 (58%) で、どれかの声に `goodhart_flag` が立つ**。今の P2-b (A) は、効果がなくても半分以上の確率で不合格を出す規則になっている。
3. 【確認+推測】今の形 `Δ > max(2 × SD, 0.05)` は、本数を増やしても必要な効果がほとんど小さくならない (80% の確率で合格するには、1 群 2〜6 本のどれでも約 0.16〜0.18)。t 検定なら本数とともに小さくなり、C の 4 本を使い回して候補を 4 本学習すると約 0.10 で合格できる。
4. 【確認】decoder だけの学習の学習 seed の揺れは、from-scratch の約 1/3 (CAM++)〜1/2 (ECAPA)。ただし予言の当たり方を確かめられる組は 1 つしかなく、decoder だけの学習は効果を CAM++ で約 1.3 倍、ECAPA で約 1.9 倍大きく見せた (向きは合っていた)。
5. 【推測】K1 は「事前に決めた向きの比較で、事前登録の外の検定では差がはっきりしている (片側 p ≈ 0.01〜0.03)」状態。仮の土台にし、次の比較の対照として新しい seed で学習して確かめ直すのが、費用と根拠の釣り合いがよい。
6. 【推測】予算は「ふるい分け (ほぼ $0〜40) → 必要なときだけ from-scratch 比較 → P4」の分かれ道を、ふるい分けの前に決めておく。3 案を §6 に書いた。

## 1. 学習 seed による揺れの分析

### 1.1 学習 seed と推論 seed の分解 (C の 4 本) 【確認】

「run の値」= 推論 seed 3 つの平均。推論 SD は 1 回の推論 seed の値の run 内 SD (4 本でまとめた)。学習 seed の SD は `run の値の分散 − 推論の分散 / 3` から出した。

| 指標 | run の値の SD | 推論 seed の SD | 学習 seed の SD (推定) | 学習 / 推論 | 4 本の最大 − 最小 |
|---|---:|---:|---:|---:|---:|
| CAM++ 正規化転写率 (日本語 5 話者) | 0.036 | 0.009 | 0.036 | 4.0 | 0.073 |
| ECAPA 正規化転写率 (日本語 5 話者) | 0.058 | 0.010 | 0.058 | 5.7 | 0.138 |
| 2.8 kHz より上のずれ (dB) | 0.80 | 0.04 | 0.80 | 18.4 | 1.71 |
| comb-HNR (dB) | 1.47 | 0.17 | 1.47 | 8.6 | 2.88 |
| CER median | 0.025 | 0.016 | 0.024 | 1.5 | 0.054 |
| つくよみ CAM++ | 0.096 | 0.021 | 0.095 | 4.7 | 0.222 |
| つくよみ ECAPA | 0.030 | 0.031 | 0.024 | 0.8 | 0.069 |

- 計画書 §7.3 の「推論 seed による振れ幅 0.026 / 0.030」は最大 − 最小の幅で、上の SD (1 回あたり) とは測り方が違う。どちらで見ても、学習 seed の揺れが支配的。
- 推論 seed を 3 つから増やしても、run の値の揺れはほとんど減らない (推論の分は run の値の分散の 2〜3% しかない)。**本数を増やすべきは学習 seed の方**。
- 【確認】K1 の 2 本は互いに近い (差 CAM++ 0.018、ECAPA 0.009、2.8 kHz より上 0.03 dB)。C の SD よりかなり小さいが、2 本では K1 の揺れが本当に小さいのかは分からない (C の SD との比の検定は有意でない)。

### 1.3 run の共通の揺れと、声ごとの揺れの分解 (日本語 5 話者、C の 4 本) 【確認、ただし声の数を増やした見込みは推測】

| encoder | run の共通の揺れ (SD) | run × 声 の揺れ (SD) | 声 5 / 10 / 15 / 20 人の平均の run の値の SD (見込み) |
|---|---:|---:|---|
| CAM++ | 0.022 | 0.063 | 0.036 / 0.030 / 0.027 / 0.026 |
| ECAPA | 0.046 | 0.075 | 0.058 / 0.052 / 0.050 / 0.050 |

- CAM++ の run 間の揺れは、大半が「その run がたまたまどの声に強いか」(run × 声) から来ている。ECAPA は全声に共通の揺れが大きい。
- 【推測】開発用の声を学習に入っていない話者で 20 人に増やすと、CAM++ の SD は約 3 割減るが、ECAPA は約 1.5 割しか減らない。費用は GPU $0 (手元の CPU の評価だけ) だが、判定に効くのは主に CAM++。候補になる話者は、学習データに入っていない Common Voice ja (CC0) の話者など (最終群とは別であることの確認が要る)。評価セットを変えるので、使うなら評価を見る前に登録する。

### 1.4 CAM++ と ECAPA の相関 【確認】

| 何の相関か | 点の数 | r |
|---|---:|---:|
| C の 4 本の run の値 (日本語 5 話者の平均) | 4 | +0.13 |
| C の 4 本 + K1 の 2 本の run の値 | 6 | +0.74 (群の差で両方が上がったため) |
| 声ごと、各声の C 平均からの run のずれ | 24 (日本語だけなら 20) | +0.09 (+0.06) |
| 同じ run・同じ声の中の、推論 seed のずれ | 108 | +0.26 |

- **同じレシピの中では、2 つの encoder は run の良し悪しをほとんど同じ向きに測っていない**。片方だけが上がる声は、効果がなくてもよく出る。
- 逆向きにはっきり動いた例: C-s1237 の 75e27ad3 は、声の C 平均から CAM++ +0.166、ECAPA −0.131。同じレシピの 1 本が、声 1 つの上では「encoder を騙す形」をそのまま作っている。
- 2.8 kHz より上のずれ (小さいほど良い) は、C の 4 本の中で CAM++ と強く連動する (r = +0.87、ずれの符号を反転して計算)。ECAPA とは +0.36。

### 1.5 同じレシピどうしで声ごとの flag が立つ率 【確認】

C の 4 本で、すべての順序つきの組 (候補・基準の 12 組) について、今の `goodhart_flag` の定義 (推論 seed ごと、同じ seed の基準と比較) を計算し直した。記録 (`summary.json` の `flags`) と一致することも確かめた。

| 数え方 | 結果 |
|---|---|
| 判定 216 回 (12 組 × 6 声 × 推論 seed 3) のうち flag | 21 回 (9.7%) |
| (組, 声) 72 個のうち、推論 seed 3 つすべてで flag | 4 個 (5.6%) |
| **12 組のうち、どれかの声で 1 回以上 flag (= P2-b A なら不合格)** | **7 組 (58%)** |

- flag は推論 seed を変えてもほぼ同じ声に立つ。つまり推論の乱数ではなく、**学習 seed の違いだけで立っている**。推論 seed を増やしても消えない。
- K1 の各 run を C の 4 本のそれぞれと比べると、どの基準を選んでも、どれかの声に flag が立つ (基準ごとに立つ声が変わる。例: C-s1235 を基準にすると 673810f3 に 3 回。C-s1235 のこの声の ECAPA が 0.566 と高いため)。

## 2. 見分けられる効果の大きさ

### 2.1 シミュレーションの前提 【推測】

- run の値 (日本語 5 話者の平均) は正規分布で、SD は CAM++ 0.036・ECAPA 0.058、2 つの相関 0.13 (C の 4 本の値)。候補の SD も同じとする。
- 効果は両 encoder に同じ大きさで入れた (K1 は CAM++ +0.10・ECAPA +0.12 でほぼ同じだった)。
- 「合格」は両 encoder とも条件を満たすこと。各 4 万回。
- **4 本から出した SD はかなり不確か**。95% の区間は推定値の 0.57〜3.7 倍 (自由度 3)。§2.4 に SD が 1.5 倍だった場合を載せた。

読み取り:

- **今の形は、本数を増やしても 0.16 前後から下がらない**。閾値が「2 × SD」で、本数で割られないため。本数を増やして得られるのは SD の推定が安定することだけ。K1 (+0.10〜0.12) のような効果は、何本学習してもこの形では通りにくい。
- 両 encoder の両方を要求するので、encoder ごとに片側 0.05 にすると、効果がないのに合格する率は全体で 0.4% 程度とかなり厳しい。**encoder ごとに片側 0.10 にしても全体で約 1%** (2 つの相関が 0.13 のとき。相関が 1 に近い最悪の場合でも 10%)。
- 【確認】学習の seed は検証用の話者の分け方も決めている (`vits/lightning.py:156-197` の `speaker_disjoint_split` が `self.hparams.seed` を使う)。同じ seed なら学習に入る話者がそろうので、対にする意味はある。ただし、共有される揺れの割合 (rho) は今のデータでは測れない (同じ seed の C と K1 の組は 2 組だけで、差は CAM++ 0.134 / 0.068、ECAPA 0.124 / 0.040)。**対にして損はないので seed はそろえ、判定は対にしない検定で行い、対にした結果は参考に並べる**のが安全。
- 【推測】ふだんの比較で 0.10 前後の効果を見分けるには、候補 4 本 + 対照 4 本 (使い回し可) が目安。0.05 前後の効果は、from-scratch では予算内で見分けられない (n = 6 対 6 でも 80% に届くのは 0.08)。

### 2.4 SD が見込みより 1.5 倍大きかった場合 【推測】

片側 0.05 + 差 0.03 で、80% で合格する効果: 3 対 3 で 0.22、4 対 4 で 0.18、6 対 6 で 0.14。C の 4 本の使い回し + 候補 3 / 4 / 6 本で 0.195 / 0.175 / 0.155。SD の推定が外れる危険があるので、使い回す場合も、新しい候補の本数は 4 本を目安にしたい。

### 2.5 二段の計画 (候補を足すかどうかを途中で決める) 【推測】

対照は C の 4 本の使い回し。1 段目: 候補 3 本で t 検定 (encoder ごと片側 0.03、差 0.03 以上)。合格なら終わり。両 encoder の差がともに +0.03 未満、またはどちらかが負なら不合格で終わり。それ以外は候補を 2 本足し、5 本で同じ検定。

| 効果 | 0 | 0.05 | 0.07 | 0.08 | 0.10 | 0.12 |
|---|---:|---:|---:|---:|---:|---:|
| 合格率 | 0.002 | 0.14 | 0.32 | 0.44 | 0.65 | 0.81 |
| 学習する本数の期待値 | 3.35 | 4.46 | 4.50 | 4.41 | 4.11 | 3.78 |

- 効果がない候補は 3.35 本で止まることが多く、費用を節約できる。各段 0.03 は厳しめに置いたので、段ごとに片側 0.05 にすれば合格しやすくなる (誤って合格する率は全体で 1% 未満のまま)。

### 3.1 学習 seed の揺れ 【確認】

### 3.2 from-scratch をどれだけ予言するか 【確認、ただし組は 1 つだけ】

日本語 5 話者の平均、正規化転写率:

| 比べたもの | CAM++ の差 | ECAPA の差 |
|---|---:|---:|
| decoder だけ: v10b + D0 差し込み − v10b (合成フィルタの固定 + MRD + decoder の学習し直し) | +0.222 | +0.292 |
| from-scratch: K1 − v10b (合成フィルタの固定 + MRD、ただし 40 epoch 対 80 epoch) | +0.168 | +0.154 |
| うち C − v10b (合成フィルタの固定、epoch の違いを含む) | +0.065 | +0.039 |
| うち K1 − C (MRD だけ) | +0.103 | +0.116 |
| 参考: decoder だけ D2-32 − D0 (差し込み) | +0.041 | +0.026 |

- 向きは合っていた。大きさは decoder だけの学習の方が CAM++ で約 1.3 倍、ECAPA で約 1.9 倍大きかった (from-scratch / decoder だけ = 0.76 / 0.53)。
- 声ごとの改善の並び (5 声) の順位相関: D0 差し込みの改善と K1 − C で CAM++ +0.5・ECAPA +0.9、K1 − v10b で +0.4 / +0.6。5 点なので弱い根拠。
- **予言の当たり方を確かめられる組は 1 つだけ**。MRD だけを decoder だけの学習で試した記録はなく、D2-32 は from-scratch で試していない。複数の候補を decoder だけの学習で並べたときの順位が from-scratch でも保たれるかは分からない。
- D1 (decoder を最初から学習) は 2 万ステップで D0 に CAM++ −0.055・ECAPA −0.086 遅れていた。**decoder の形を変える候補 (新しい重みが要る) は、短い decoder だけの学習では不利に出る**。比べるときは、同じく最初から学習した今の形 (D1 と同じ作り方) を対照に置く必要がある。

### 3.3 ふるい分けへの使い方 【推測】

- 落とす側には使える: decoder だけの学習で両 encoder の改善が +0.04 未満 (§3.4 の見分けられる大きさ) の候補は、縮む割合 0.5〜0.75 を掛けると from-scratch で +0.03 未満になり、from-scratch の比較 (0.10 前後が見分けの下限) に出しても判定できない。
- from-scratch に進める目安: decoder だけの学習で両 encoder とも +0.15 以上 (0.10 ÷ 0.5〜0.75 ≈ 0.13〜0.20)。
- 例外: 調査の A 案 (合成経路の z でも decoder を学習する) は、from-scratch の学習のあとに足す 2 段目の工程なので、**decoder だけの学習の結果がそのまま本番のレシピの結果になる**。from-scratch の比較は要らず、P4 の後に同じ形で確かめればよい。

### 3.4 ふるい分けの比べ方 (案) 【推測】

- 土台: 今ある from-scratch の 6 本 (C の 4 本、K1 の 2 本、ep40 の EMA)。v10b ではなく、次の土台に近いものを使う。
- 群: (0) 延長だけ (今の decoder の学習を同じステップ数だけ続ける)、(A) 合成経路の z を混ぜる、(X) ほかの候補。同じ土台の (A) − (0) を対にする。延長だけの群を置くのは、「decoder を余分に学習したこと」自体の効果を差し引くため。
- 評価は §7.10 と同じ差し込み (合成経路、推論 seed 3 つ、`--encoder2`)。
- 揺れの見込み: 2 段目の学習 seed の SD が差し込みと同じ (0.013 / 0.026) なら、対の差の SD は 0.018 / 0.037、6 土台で 80% の確率で合格する効果は CAM++ 約 0.02、ECAPA 約 0.04 (片側 0.10)。差 0.03 以上も求めるので、実際の下限は約 0.04。
- 2 段目の学習 seed の揺れを測るため、2 つの土台で (0) を学習 seed 2 本ずつ回す (候補の結果を見る前に)。
- 土台ごとに効果が違う可能性 (C の土台には MRD がない) があるので、C の土台 4 本と K1 の土台 2 本は分けても並べる。

### 4.2 事前登録できる形の案 【推測】

以下は、次の比較で使う規則の案。数値は本書の計算に基づくが、採用と細部はユーザーが決める。

> **対象の値**: 各 run の ep40 の EMA を、開発群 (日本語 5 話者 + つくよみ) で、推論 seed 42/43/44 × 参照 2 本で評価する (§6 P2 と同じ手順)。「run の値」は推論 seed 3 つの平均。「群の平均」は run の値の平均。標準偏差は n−1 で割る。
>
> **Q-a (効果)**: CAM++ と ECAPA のそれぞれで、日本語 5 話者の平均の正規化転写率について、Δ = 候補群の平均 − 対照群の平均 が次の両方を満たす。(1) Δ ≥ +0.03。(2) 等分散を仮定した 2 群の t 検定 (自由度 = 候補の本数 + 対照の本数 − 2) で、片側 p < 0.10。両 encoder とも満たしたら合格。
> - 理由: 効果がないのに合格する率は全体で約 1% (2 つの encoder の相関 0.13 のとき、最悪でも 10%)。+0.03 は計画書 §3.3 の「±0.03 未満は判定材料にしない」。
> - 対照に今ある C の 4 本 (または K1 の本数) を使い回す場合は、同じコード・同じ学習の引数 (seed と出力先以外)・同じ GPU の種類 (L40S) であることを条件にする。新しいフラグを足したコードを使う場合は、フラグを切ったときに C と同じ損失が出ることを手元の CPU のテストで確かめる。
> - p は 3 桁に丸めて比べ、境目はあらかじめ決めた側に倒す (例: p = 0.100 は不合格)。
>
> **Q-b (encoder を騙す方向)**: 次の 3 つをすべて満たす。
> (1) 日本語 5 話者の群平均で、Δ が CAM++ +0.02 以上かつ ECAPA +0.01 未満にならない (P2′-b B(1) と同じ)。
> (2) `above_ceiling_flag` がどの評価でも true でない。
> (3) 6 声のそれぞれで、群平均の差 (正規化転写率) が CAM++ +0.05 以上かつ ECAPA −0.05 以下の声が 2 声以上ない。1 声だけのときは、その声を記録し、合否には使わない。
> - 声ごとの `goodhart_flag` (1 本対 1 本、`--baseline` に対照の 1 本目) は、これまでどおり計算して記録するが、合否には使わない。理由: 同じレシピの C どうしで 12 組中 7 組に立った (本書 §1.5)。
>
> **Q-c (明瞭さ)**: CER の median が、候補のどの評価でも 0.30 以下 (P2-c と同じ)。
>
> **Q-d (音質)**: 2.8 kHz より上のずれで、候補群の平均が対照群の平均 + 0.5 dB 以下。0.5 dB は、計画書 §7.9 で耳で聞き分けられなかった差 (0.4〜0.6 dB) の上の端。
> - 注意: 今の「対照群の平均以下」は、音質に効かない候補でも約半分の確率で落とす (2.8 kHz より上のずれの run 間の SD は 0.8 dB と大きい)。+0.5 dB の幅を入れても、効果のない候補を 2 割前後落とす【推測、正規分布の概算】。音質を狙わない候補で厳しすぎるなら、「候補群の方が悪く、かつ t 検定の片側 p < 0.10 のときだけ不合格」(効果のない候補を落とす率 10%) も選べる。
>
> **本数と足し方**: 候補 4 本 (学習 seed は対照とそろえる)。二段にするなら、1 段目 3 本、灰色 (§2.5 の条件) なら 2 本足して 5 本。足すかどうかの条件は学習の前に登録し、それ以外の理由では足さない。

## 5. K1 の扱い

### 5.1 今ある根拠の強さ 【確認 + 推測】

- 【確認】K1 対 C は P2 で事前に登録した比較で、「K1 の方が良い」という向きも事前に決まっていた。不合格になったのは、規則の形 (2 × SD、1 本対 1 本の声ごとの flag) のため。
- 【確認】事後の検定: 等分散の t 検定で片側 p ≈ 0.010 (CAM++)・0.028 (ECAPA)。Welch の t 検定では 0.003・0.013。効果の大きさは両群をまとめた SD の 3.3 倍 (CAM++)・2.3 倍 (ECAPA)。
- 【確認】並べ替えの検定 (6 本から 2 本を選ぶ 15 通り) では、K1 の 2 本が CAM++・ECAPA・2.8 kHz より上のずれの 3 つすべてで上位 2 本になるのは 15 通り中 1 通り (p = 1/15 = 0.067)。2 本対 4 本では、どんなにはっきりした差でも p は 0.067 より小さくならない (並べ替えでは 3 対 3 でやっと 0.05 に届く)。
- 【推測】弱める点: (1) 検定の形を結果を見たあとで選んでいる。(2) 2 本の K1 の揺れが小さいのは偶然かもしれず、t 検定の p はそれに頼っている部分がある (Welch の方が小さく出るのはこのため)。(3) 2 本で測った効果は、本当の効果より大きく出やすい (確かめ直しの見込みは 0.08 程度で立てるのが安全)。
- 【推測】強める点: (1) 両 encoder と 2.8 kHz より上のずれの 3 つが同じ向き。(2) MRD は音声のスペクトルだけを見る判別器で、話者の encoder を使わないので、encoder を騙す方向に働く道筋がない。(3) 推論の大きさ・速さ・メモリは変わらない (P2-f 合格済み)。採って外れても、学習の時間が約 17% 増えるだけ。

### 5.3 私の勧め 【推測】

## 6. 残り $742 の配分案

前提 【推測、費用は実績からの見込み】:

- from-scratch 40 epoch (L40S): C 型 約 $37〜39、K1 型 約 $44〜46。データの準備は VM ごとに約 $5 (2 GPU) 〜 $15 (5 GPU)。
- P4 (80 epoch、L40S、K1 型): 1 本 約 $88〜92。2 本で約 $180、遅い box や再実行の余裕を入れて約 $250。RTX 5090 が借りられれば 1 本 約 $25〜30 で、大きく下がる (batch の違いは要確認)。
- decoder だけの学習: 手元の GPU なら $0 (1 本 3〜5 時間)、借りても 1 本 約 $1〜6。
- 計画書 §2 の配分: P3 $50、P4 $400、予備 $250。P2 の配分 $300 はほぼ使った (P2 + P2′ で約 $252.5)。

### 案 1: ふるい分け → 1 回の from-scratch 比較 (K1 の確かめ直しを兼ねる) → P4

| 段 | 内容 | 費用 |
|---|---|---:|
| 0 | (e) 評価セットの拡張と ep30 の評価 (手元) | $0 |
| 1 | ふるい分け: 6 本の土台 × (延長だけ、A、ほか 1〜2 候補)、§3.4 の形 | $0〜40 |
| 2 | from-scratch: K1 ×2 (s1236・s1237) + K1 + X ×4 (s1234〜s1237)。X はふるい分けで +0.15 以上の候補 | 約 $285 |
| 3 | P4: 段 2 の勝ち (+ A) を 80 epoch × 2 本 | 約 $250 |
| 計 | | 約 $535〜575 (残り 約 $165〜205 を P3 と予備に) |

- 向くとき: ふるい分けで、from-scratch が要る候補 (decoder の形の変更など) に大きな改善が出たとき。
- 注意: X が flow の縮小を含むなら、P2-g と同じく flow の縮小だけの群 (2 本、約 $90) が要り、合計が約 $650 まで増える。

### 案 2: ふるい分け → K1 の確かめ直し → P4 (from-scratch の比較はしない)

| 段 | 内容 | 費用 |
|---|---|---:|
| 0 | (e) | $0 |
| 1 | ふるい分け (案 1 と同じ)。A のような 2 段目の工程はここで判定が済む | $0〜40 |

| 計 | | 約 $390〜430 (残り 約 $310〜350 を P3 (データ拡充) と予備に) |

- 向くとき: ふるい分けで残ったのが 2 段目の工程 (A など) だけのとき、または decoder の形の変更の改善が +0.15 に届かなかったとき。
- データを広げる P3 (Common Voice ja、Emilia-YODAS ja) に予算を残せる。

### 案 3: 大きな構成の変更 (flow を縮めて decoder を大きくする) を確かめる

| 段 | 内容 | 費用 |
|---|---|---:|
| 0〜1 | 案 1 と同じ。decoder の形を変える候補は、最初から学習した今の形を対照に置く (§3.2) | $0〜40 |
| 2 | from-scratch: K1 + X ×4、K1 ×2 (s1236・s1237)、K1 + flow の縮小だけ ×2 | 約 $375 |
| 3 | P4 | 約 $250 |
| 計 | | 約 $625〜665 (残り 約 $75〜115) |

- 向くとき: ふるい分けで、flow の縮小が前提の候補 (D2-32、AdaIN、調査の B 案) が両 encoder で +0.15 以上を出したとき。
- 予備がほとんど残らないので、P4 の再実行や P3 はできない前提になる。

### 分かれ道の決め方 (ふるい分けの前に登録する案) 【推測】

1. ふるい分けで、from-scratch が要る候補のうち、両 encoder で +0.15 以上 (§3.3) かつ Q-b(3) に当たらないものがあれば、案 1 (flow の縮小を含むなら案 3)。
2. そうでなく、2 段目の工程 (A など) が Q-a の形 (対の差、片側 0.10、差 0.03 以上) に合格したら、案 2 で P4 に A を入れる。
3. どれも残らなければ案 2 で、P4 は K1 のまま。浮いた予算は P3 に回すか、計画を立て直す。

## 7. 確かめていないこと

- 学習 seed をそろえたときに共有される揺れの割合 (rho)。今のデータでは測れない。
- K1 の揺れが C より本当に小さいか (2 本しかない)。
- decoder だけの学習の順位が from-scratch でも保たれるか (確かめられる組が 1 つだけ)。
- 2 段目の decoder の学習 (A 案) の、学習 seed による揺れ (P1 の値で代用した)。
- 開発用の声を増やしたときの SD の見込み (新しい声が今の 5 声と同じように振る舞うと仮定した)。
- RTX 5090 で batch 32 の学習ができるか、L40S の run と同じ分布の結果になるか。
- 2.8 kHz より上のずれの +0.5 dB の幅で、効果のない候補を落とす率 (正規分布での概算のみ)。
