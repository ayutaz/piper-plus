# piper-plus の音質改善の調査 (2026-11-03)

> 付録: 2026-11-03 にサブエージェントが書いた調査報告を、本文を変えずに収めたもの (手元の作業用フォルダのパスだけ除いた)。要約と確認の状況は [../zero-shot-improvement-survey-2026-11-03.md](../zero-shot-improvement-survey-2026-11-03.md) にある。数値や論文の主張には、要約側で確かめられなかったと書いたものがある。


対象: 調波の間のざらつき (2.8 kHz より上の帯域に decoder が足す雑音、1〜3 kHz の調波の間の雑音) と、自然さ・抑揚の平板さ。
範囲: 2024〜2026 年の論文と公開実装、本リポジトリの issue・PR・コミット・設計書。リポジトリとリモートには何も変更を加えていない。

表記:
- **[出典で確認]** 論文本文・表・公式リポジトリを開いて確かめた内容
- **[推測]** 本書の見立て。測っていない
- 数値の比較の注意: 論文の数値は、ほぼすべて 24 kHz、メル入力のボコーダー単体 (LibriTTS) の値。piper-plus は 22.05 kHz、潜在表現 z を入力にする VITS の decoder なので、**効果の大きさはそのまま持ち込めない**。持ち込めるのは「何に効いたか」の向きだけ。

## 0. 要約

- 今の雑音は decoder が作る上の 3 帯域 (2.8 kHz より上) にあり、再構成でも出る (計画書 §7.8〜7.9)。v10b 残存ノイズ診断の結論は「decoder が z の細かい内容を、調波に揃わない形で波形にしている」。**波形の位相の揃い方を直接見る学習の仕組みが、今の損失と判別器の組み合わせには無い。** ここを埋める候補が上位に来る。
- 上位 3 つはどれも**学習のときだけ働く変更**で、配布する ONNX の大きさ・速さ・メモリは変わらない (制約 1.03 倍に響かない)。
  1. 帯域ごとの位相の損失 (振幅で重みを付ける)。SCNet (Interspeech 2026) と APNet の位相の損失。
  2. 調波を見る判別器 (UnivHD、2025-12) または CQT 判別器 (MS-SB-CQT)。今の帯域分割 MRD に足す。
  3. GAN の損失の形を変える (SAN、または相対比較型の損失 + R1/R2 の勾配の罰則)。
- 4 位以下は推論の計算が少し増える (Snake 活性化、下の帯域を手がかりに上の帯域を作る条件ネット) か、抑揚の改善 (確率的な F0 予測)。
- 進め方: **P1 の「decoder だけを学習して比べる道具」(`tools/train_decoder_only.py`、v10b の事後エンコーダーを固定) で、上位 3 つを 1 案あたり約 $1〜2 で先にふるいにかける**。P2 で分かった学習 seed による幅 (C の 2 本で ECAPA 0.094) を考えると、from-scratch の比較は 1 群 2 本以上が要り、1 回の比較で約 $75〜90 かかる。残り約 $550 なら from-scratch の比較は 2〜3 回が限度。

## 3. 候補 (順位付き)

### 候補 1: 帯域ごとの位相の損失 (振幅で重み付け)

- **何か**: 生成した音と実録音の STFT の位相の差を、2π の折り返しが効かない形 (−cos や sin²(Δθ/2)) で測り、実録音の振幅で重みを付けて損失にする。振幅の小さい (雑音らしい) bin の位相は強く縛らない。
- **出典**:
  - SCNet: arXiv [2609.10025](https://arxiv.org/abs/2609.10025) (2026-09-09、Interspeech 2026 採択)、Nan Xu, Mingxue Yang。コード [github.com/vspeech/SCNet](https://github.com/vspeech/SCNet) (MIT)、HF `vspeech/SCNet` (Apache-2.0 表記)。**[出典で確認]** 損失は `L_pha = M · sin²(Δθ/2)`、Δθ = min(|θ̂−θ|, 2π−|θ̂−θ|)、M は実録音の振幅。
  - APNet: arXiv [2305.07952](https://arxiv.org/abs/2305.07952) (2023)。**[出典で確認]** 瞬時位相、群遅延 (周波数方向の差)、位相の時間差 (時間方向の差) の 3 つ。どれも −cos で折り返しを避ける。
  - 参考: FA-GAN arXiv [2407.04575](https://arxiv.org/abs/2407.04575) (2024) の複素 (実部・虚部) の多解像度損失。**[出典で確認]** 要旨のみ、数値なし。
- **piper-plus での変更**: `vits/lightning.py` の生成器の損失に 1 項足す (opt-in のフラグ、既定 0)。
  - 正解: 実録音の区間 `y` を固定の PQMF 分析フィルタで 4 帯域に分ける (sub-band STFT 損失と同じ材料)。
  - 生成: 合成フィルタの前の 4 帯域の出力。
  - 両方を同じ STFT (例: 帯域ごとに n_fft 64/128、加えて head と同じ 16 点) にかけ、SCNet 式の振幅で重みを付けた位相の差、必要なら群遅延と時間差の項も足す。帯域ごとに平均し、band1〜3 の重みを指定できるようにする。
  - 推論の計算グラフは変わらない。
- **報告された効果** [出典で確認]:
  - SCNet の除去実験 (0.5M step、LibriTTS 24 kHz、iSTFTNet の骨組み): 位相の損失を外すと PESQ 3.90 → 3.80、M-STFT 0.768 → 0.787、ピッチ誤差 21.86 → 24.54 (同じ分布内)。重みなしの位相の損失は重み付きとほぼ同じ (3.78)。
  - APNet の除去実験 (解析合成): 位相の損失を 3 つとも外すと F0 誤差 19.8 → 40.5 cent、MCD 0.77 → 0.99 dB、有声・無声の誤り 3.1 → 5.8%。
  - 比較の注意: どちらも位相を直接出力するメル入力のボコーダー。piper-plus の head も位相を直接出す (`phase = π·sin(x)`、`mb_istft.py`) ので形は近いが、入力は z。
- **制約への合い方**: 学習のときだけ。ONNX の大きさ・速さ・メモリは変わらない。6 ランタイムに影響なし。実録音を正解にした損失なので契約 §2 の禁止の対象外 (`--c-hiband-stft` と同じ扱い)。
- **手間と GPU**: 実装は約 100〜150 行 + テスト。ふるいは decoder だけの学習で 1 案 2 seed 約 $1〜2 (P1 の実績 6 本 $5.4 から)。
- **リスク**:
  - z は振幅スペクトルから作るので、実録音の細かい位相は z に入っていない。位相を強く縛ると、GAN が作る自然なばらつきを潰して、こもった音や平らな音になるおそれ **[推測]**。係数を小さく始め、2.8 kHz より上のずれと聞き比べで確かめる。
  - 帯域ごとの STFT の窓と hop の取り方で、位相の基準がずれる。実録音どうしで損失が 0 になる単体テストを最初に書く。
  - 「雑音の多い帯域にも位相を合わせよ」となると、雑音を消す方向ではなく、雑音を実録音の位相に寄せる方向に効くかもしれない。振幅の重みはそのための仕組みだが、効くかは測るまで分からない。
- **過去に試したか**: 試した記録はない (§2)。

### 候補 2: 調波を見る判別器 (UnivHD) または CQT 判別器 (MS-SB-CQT) を足す

- **何か**: STFT の上に、周波数ごとに幅を学習できる三角の帯域フィルタを置き、調波の中・調波どうしの関係を見る判別器 (UnivHD)。または、低い周波数ほど細かく分ける定 Q 変換 (CQT) の上で、オクターブごとに帯域を分けて見る判別器 (MS-SB-CQT)。
- **出典**:
  - UnivHD: arXiv [2512.03486](https://arxiv.org/abs/2512.03486) (2025-12-03)、Nan Xu ほか。**コードの公開なし、ライセンス記載なし** [出典で確認]。判別器 0.31M パラメータ。
  - MS-SB-CQT: arXiv [2311.14957](https://arxiv.org/abs/2311.14957) (2023-11)、Gu ほか。続報 arXiv [2404.17161](https://arxiv.org/abs/2404.17161) (2024-04、CQT + ウェーブレット)。実装は [Amphion](https://github.com/open-mmlab/Amphion) `egs/vocoder/gan/tfr_enhanced_hifigan` (リポジトリは MIT)。
- **piper-plus での変更**: `vits/models.py` に判別器クラスを足し、`lightning.py` の判別器の一覧に opt-in で加える (帯域分割 MRD と並べる)。UnivHD は論文から作り直す。CQT は Amphion の実装を移植する (`nnAudio` 依存の有無を要確認)。
- **報告された効果** [出典で確認] (UnivHD 論文の表 I、LibriTTS 24 kHz、1.5M step、同じ分布内 / 分布外):
  - iSTFTNet: PESQ 2.95/2.81、MOS 3.91/3.85 → CQT を足す 3.01/2.84、4.01/3.91 → UnivHD を足す 3.07/2.88、4.03/3.99。F0 誤差 43.4 → 40.0。
  - HiFi-GAN: MOS 3.85 → 4.05 (UnivHD)。論文は CQT 判別器が奇数次の調波を捉えられないと指摘。
  - MS-SB-CQT の要旨: 歌声で HiFi-GAN の MOS 3.27 → 3.87 (話し声の数値は要旨にない)。
- **制約への合い方**: 学習のときだけ。推論に影響なし。
- **手間と GPU**: UnivHD は作り直しで中程度 (論文の記述だけで再現する必要)。CQT は移植で中程度。学習は判別器が増える分だけ遅い (K1 の帯域分割 MRD で 1 epoch 69 → 77 分の例) **[推測で同程度]**。ふるいは decoder だけの学習で 1 案約 $1〜2。
- **リスク**:
  - 判別器を増やすと敵対的な圧力が増し、v11 のように崩れる余地が増える。P2 の C には共進化の話者識別器・JCU MRD・WavLM 判別器がすでに入っている。
  - UnivHD の学習できるフィルタは判別器側の部品なので、生成器側の「学習できる部品が抜け道になる」問題 (合成フィルタのずれ) とは別。ただし判別器が低い帯域ばかり見るように育つと H2 (上の帯域を見ていない) が戻る。帯域分割 MRD は残す。
  - 著者 (Nan Xu) は SCNet と同じで、判別器と位相の損失の両方の効果を同じ著者が報告している。独立の再現はまだない。
- **過去に試したか**: 試した記録はない。UnivHD は P1 設計書 §3 で「全候補に共通で入れる」候補として挙がったが、実際に入ったのは帯域分割 MRD だけ。

### 候補 3: GAN の損失の形を変える (SAN、または相対比較型 + R1/R2)

- **何か**:
  - SAN: 判別器の最後の線形層を単位ベクトルに正規化し、勾配を止める位置を変えて、判別器が「本物と偽物を分ける最適な向き」を見つけやすくする。最小二乗の GAN の損失を softplus で単調にする改変を含む。
  - 相対比較型 (RpGAN) + R1/R2: 判別器が「本物と偽物のどちらがより本物らしいか」を対で判定し、本物・偽物の両方に勾配の大きさの罰則を付ける。
- **出典**:
  - BigVSAN: arXiv [2309.02836](https://arxiv.org/abs/2309.02836) (ICASSP 2024、Sony)、コード [github.com/sony/bigvsan](https://github.com/sony/bigvsan) (MIT) [出典で確認]。
  - RAF: arXiv [2603.11678](https://arxiv.org/abs/2603.11678) (2026-03-12、KAIST)。匿名リポジトリのみ、ライセンス記載なし [出典で確認]。
  - R3GAN: arXiv [2501.05441](https://arxiv.org/abs/2501.05441) (NeurIPS 2024、画像)。
- **piper-plus での変更**: `vits/losses.py` の `discriminator_loss` / `generator_loss` に別の形を足し、`models.py` の各判別器 (MPD、MSD、MRD、帯域分割 MRD) の最後の層を SAN 用に切り替えられるようにする。WavLM 判別器と話者識別器は今のままにする (変数を減らすため)。
- **報告された効果** [出典で確認]:
  - BigVSAN (LibriTTS、1M step、著者による BigVGAN の再現との比較): M-STFT 0.838 → 0.788、PESQ 3.86 → 4.12、周期性の誤差 0.116 → 0.094、V/UV F1 0.954 → 0.964、MOS 3.19 → 3.24 (幅が大きく差は小さい)。Parallel WaveGAN の FAD (LibriTTS) 1.41 → 0.87。
  - RAF の除去実験 (0.2M step、BigVGAN-base): 最小二乗 GAN から RpGAN + 罰則に替えるだけで PESQ 3.12 → 3.18、UTMOS 3.19 → 3.30。RAF 全体 (SSL モデルの距離を使う) では 1M step で UTMOS 3.45 → 3.65。学習時間は 5.9 → 9.4 日。
- **制約への合い方**: 学習のときだけ。推論に影響なし。
- **手間と GPU**: SAN は公式コードがあり小さい (損失と最終層の数十〜100 行)。RpGAN + R1/R2 も小さいが、R1/R2 は判別器の入力に対する勾配を取るので、判別器の学習が 1.3〜2 倍遅くなる **[推測]** (RAF は 7 step ごとに罰則を掛けて軽くしている)。
- **リスク**:
  - **RAF の全体は採らない**。判別器に WavLM・HuBERT の距離 (固定モデルの点数) を当てさせる形で、契約 §2-4 (固定 encoder の点数を学習の目標にしない) と衝突する。使うのは相対比較 + 罰則の部分だけ。
  - GAN の損失の形を変えると、損失の係数 (mel 45 など) の釣り合いが変わる。ふるいで崩れないかを先に見る。
  - 改善の報告は主に PESQ・M-STFT・周期性で、上の帯域のざらつきに効くかは分からない **[推測]**。
- **過去に試したか**: 試した記録はない (§2)。

### 候補 4: decoder の活性化を LeakyReLU から Snake に替える

- **何か**: Snake は x + sin²(αx)/α の形の活性化で、周期的な信号を作りやすい。BigVGAN・SCNet・Pupu-Vocoder が使う。
- **出典**:
  - SCNet ([2609.10025](https://arxiv.org/abs/2609.10025)) の骨組みは「iSTFTNet の LeakyReLU を Snake に替えたもの」[出典で確認]。
  - Pupu-Vocoder: arXiv [2512.20211](https://arxiv.org/abs/2512.20211) (2025-12、v3 2026-06)。歌声での除去実験で、提案の活性化 (2 倍オーバーサンプリング + ADAA を掛けた SnakeBeta) を LeakyReLU に替えると CMOS −1.45、素の SnakeBeta で −0.52、オーバーサンプリングなしで −0.38、ConvTranspose に戻すと −0.15 [出典で確認]。**話し声での除去実験はない。ライセンスの記載なし。**
- **piper-plus での変更**: `mb_istft.py` の resblock と upsample の前の `F.leaky_relu` を、チャンネルごとの α を持つ Snake に替える opt-in のフラグ。α は対数で持ち、範囲を固定する (学習できる部品に制約を付ける、v11 の教訓)。ConvTranspose はすでに `--upsample-mode resize` で置き換え済みなので、Pupu の残りの要素はこの活性化だけ。
- **報告された効果**: 上のとおり。話し声・VITS の decoder での数値はない。
- **制約への合い方 [推測]**: decoder の要素ごとの計算が増える (sin、掛け算)。畳み込みに比べて小さいが、decoder の時間の 2〜5%、全体で 1〜3% 程度増えると見る。K1 の p50 は 1.025 倍なので、**上限 1.03 倍を超えるおそれがある**。ランダムな重みの試作 ONNX で `measure_variant_cost` を先に測る ($0)。Sin は ONNX の標準の演算で、MB-iSTFT の位相ですでに使っているので 6 ランタイムで動く。FP16 の変換は `tools/convert_fp16.py` の FP32 に残す演算の一覧を要確認。オーバーサンプリング付き (Pupu の本来の形) は計算が倍近くになるので採らない。
- **手間と GPU**: 実装は小さい。ふるい約 $1〜2 + 速さの測定 $0。
- **リスク**: MB-iSTFT の活性化は 1 帯域あたり 1.4 kHz のフレームの格子で働いていて、時間波形の上でエイリアシングを起こす Pupu の状況とは違う。効く理由がそのまま当てはまるとは限らない **[推測]**。
- **過去に試したか**: Snake は試した記録はない。BigVGAN 型のエイリアシング対策は v10b 品質計画 H-4 で条件付きのまま。

### 候補 5: 下の帯域を手がかりに上の帯域を作る (SCNet の帯域条件ネット)

- **何か**: 小さな条件ネットが低い帯域 (SCNet では 0〜3 kHz、6 kHz サンプリング) の波形を先に予測し、それを STFT にかけた複素スペクトルを本体に入れる。上の帯域を作るとき、下の帯域の倍音の位置と位相が手がかりになる。
- **出典**: SCNet [2609.10025](https://arxiv.org/abs/2609.10025)、条件ネットは ConvNeXtV2 4 ブロック、全体 15.86M [出典で確認]。
- **piper-plus での変更 [推測]**: MB-iSTFT の band0 (0〜2.76 kHz) は、SCNet の低い帯域とほぼ同じ範囲。band0 の head の出力 (振幅と位相、またはその iSTFT 波形を STFT し直したもの) を、band1〜3 の head の入力に連結する。新しい条件ネットは足さず、今の decoder の中で「band0 を先に作り、上の帯域はそれを見て作る」順にする形が最も安い。
- **報告された効果** [出典で確認] (除去実験 0.5M step): 条件ネットを外すと PESQ 3.90 → 3.31、M-STFT 0.768 → 0.874、ピッチ誤差 21.9 → 34.3。本論文の中で最も大きい差。
- **制約への合い方 [推測]**: head の入力が増える分と、band0 の再 STFT の分で、decoder が 5〜10% 重くなる。単独では 1.03 倍に収まらない見込みで、flow を 4 → 3 段に縮める (P1 設計書 §7.4、P2-g の Cf 群が必要) と組み合わせることになる。
- **手間と GPU**: 中〜大。decoder の形が変わるので、ふるいは decoder だけの学習 (D1 のように最初から学習、20k step で D0 に追いつかなかった例あり) で長めに回す必要がある。
- **リスク**: v11 の carrier head (band0 にだけ調波の担体を入れた) と考え方が近い。v11 が崩れた原因は話者の敵対的な学習とされたが、確定はしていない。decoder の中で帯域どうしの順序を作ると、band0 の誤りが上の帯域に伝わる。
- **過去に試したか**: 近いものとして v11 carrier head (eea5fabe、band0 のみ、崩壊) と P1 の D3 案 (担体を全 4 帯域に、未実施)。**新しい根拠は SCNet の除去実験の大きな差**だが、SCNet の条件は F0 ではなく波形の予測なので、v11 の「F0 を正しく予測できないと崩れる」弱点とは別の形にできる。ユーザーの指示どおり、担体そのものの再提案ではなく、F0 を使わない形に限る。

### 候補 6: 抑揚: 確率的な F0 予測 (flow 型) を text 側に入れる

- **何か**: F0 を平均に寄せて回帰するのではなく、小さな flow で F0 の分布から引く。予測した F0 を prior (enc_p の出力) か flow の条件に入れる。
- **出典**:
  - Ogun ほか, Interspeech 2023, arXiv [2305.17724](https://arxiv.org/abs/2305.17724) (CC BY 4.0、コードのリンクなし) [出典で確認]。Glow-TTS (54.5M) に確率的な継続長と F0 の予測を足して 56.0M。
  - 参考: Period VITS arXiv [2210.15964](https://arxiv.org/abs/2210.15964) (ICASSP 2023)、PITS arXiv [2302.12391](https://arxiv.org/abs/2302.12391)。
- **piper-plus での変更 [推測]**: 既存の F0 予測 (`--use-f0-path`、L1 回帰) を、確率的継続長予測 (`StochasticDurationPredictor`) と同じ形の小さな flow に替え、出力を decoder ではなく enc_p の出力 (prior の平均) の側に足す。S-2 で decoder が F0 を無視した (追従率 0.0) ので、入れる先を decoder から prior に移すのが要点。
- **報告された効果** [出典で確認] (未知の 6 話者、VCTK/LibriTTS): N-MOS 3.13 (基準) → 3.31 (確率的継続長) → 3.45 (+ 確率的 F0)。男性で +0.29。長文の NR-MOS 3.26 → 3.39。話者の類似は変わらず。
- **制約への合い方 [推測]**: 確率的継続長予測と同程度の小さな flow で、パラメータ数十万、音素の数だけの計算。全体の p50 で +1% 未満と見る。ONNX の入出力は変わらない。
- **手間と GPU**: 中。from-scratch の学習が要る (decoder だけの学習では測れない)。
- **リスク**:
  - F0 の統計を学習の損失にすることは禁止 (契約 §2-4)。この案の損失は「予測器の出力 対 実録音の F0」の尤度で、S-2 設計書 §5.4 の「明示された例外」の範囲に入る。範囲を守る。
  - VITS は z の段階で音高を持っているので、prior に F0 を足しても flow がそれを使わないおそれ (S-2 の失敗と同じ形) **[推測]**。F0 をずらして出力が追従するかの単体の判定を先に置く (S-2 の Phase D と同じ)。
  - 抑揚を広げると、上の帯域のずれも増える (計画書 §7.9: noise_scale 0 → 0.667 で 2.8 kHz より上のずれ +2.00 → +3.41 dB)。雑音の対策を先に済ませる。
- **過去に試したか**: L1 回帰の F0 予測と decoder への注入は S-2 (974a3f0a) で不発。確率的な F0 予測と prior への注入は試した記録はない。

### 候補 7 (参考): 帯域ごとの iSTFT を 16 → 32 点 (D2-32) と flow 3 段

- **何か**: 1 帯域の周波数の分解能を倍にする。すでに P1 で合格し、数値は D0 を上回った (上の帯域 −0.28 dB、CAM++ +0.064、ECAPA +0.051、計画書 §7.10)。
- **新しい文献の裏付け**: 「Revisiting Vocos」arXiv [2607.24323](https://arxiv.org/abs/2607.24323) (2026-07、IWAENC 2026) は、Vocos 型は振幅は作れるが位相が苦手で、1 次元の畳み込みが位相の差の予測を妨げると報告 [出典で確認、要旨]。「Rethinking the joint estimation of magnitude and phase」arXiv [2509.18806](https://arxiv.org/abs/2509.18806) (2025-09) は、振幅と位相を別々に出す APNet2 が大きなデータで崩れたと報告 [出典で確認、要旨]。どちらも「位相の作り方が弱点」を支持し、候補 1 (位相の損失) と D2-32 を組み合わせる理由になる **[推測]**。
- **制約**: flow を 4 → 3 段に縮めないと収まらない (P1 設計書 §7.4)。新しい提案ではなく、P2′ の次の手として計画済み。

## 4. 進め方の提案 (GPU 残り約 $550)

1. **ふるい (約 $10〜20、P1 と同じ道具と手順)**: v10b の事後エンコーダーを固定し、D0 の構成を土台に、候補 1・2・3 (と 4) を 1 つずつ足して decoder だけを 2 万 step、学習 seed 2 本で学習する。判定は P1 と同じ再構成の指標 (2.8 kHz より上のずれ、話者の正規化転写率の両 encoder、comb-HNR は参考) と、伏せた聞き比べ。**判定の閾値は学習の前に設計書へ書く**。
   - 候補 4 (Snake) は、学習の前にランダムな重みの試作 ONNX で速さを測る ($0)。1.03 倍を超えるなら学習しない。
2. **組み合わせ (約 $5)**: 効いた案を足し合わせ、同じ道具でもう一度確かめる。
3. **from-scratch の比較 (約 $75〜90)**: 組み合わせを 2 本、C の 4 本 (P2′) と比べる。from-scratch の 1 本は約 $37。
4. **抑揚 (候補 6)** は、雑音が減ってから from-scratch で 2 本 (約 $75)。
5. 残り (約 $350) は P4 の本学習に回す。

注意: P1 の §7.10 では、decoder の改善は TTS でもほぼ残った (話者の値) が、上の帯域のずれは再構成ほど下がらなかった (再構成 1.9 dB、合成 3.0 dB)。prior・flow が作る z の側にも雑音の元がある。ふるいで良くても、合成で同じだけ良くなるとは限らない。
